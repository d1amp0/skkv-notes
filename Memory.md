--- 
## Основные сегменты памяти

### 1. Стек

- Это область памяти, отвечающая за выполнение функций и хранение локальных переменных.
- Управляется компилятором и процессором автоматически.
- Размер ограничен несколькими МБ.

### 2. Куча

- Это область памяти для динамического выделения.
- Управляется программистом.
- Размер ограничен только физической памятью.

### 3. Секция данных и кода

- Это область памяти, отвечающая за хранение глобальных и статических переменных, а также самого кода программы.
- Управляется ОС.
- Размер фиксирован при запуске программы.

## Динамическое выделение памяти

Зачастую происходит такое, что размер данных неизвестен на этапе компиляции. Самым простым примером такого является `VLA (Variable Length Array)` — массив переменной длины. Тогда нужно использовать динамическое выделение памяти. Как было сказано выше, динамическая память выделяется в куче. Для выделения памяти существует несколько стандартных функций:
### `malloc` (memory allocation)

Функция `malloc` просто выделяет запрошенный объем памяти и ничего более.

```c
int *p = malloc(5 * sizeof(int));
```

- выделяет запрошенный в байтах блок памяти;
- внутри выделенного блока находится мусор;
- если памяти не хватило, то возвращает `NULL`.

--------------------------------------------------------------------------------
### `calloc` (contiguous allocation)

Функция `calloc` создана для безопасного выделения памяти под массивы с автоматическим обнулением.

```c
int *p = calloc(5, sizeof(int));
```

- выделяет память под запрошенное число элементов запрошенного размера;
- внутри выделенного блока находятся нули;
- работает дольше, чем `malloc`;
- если памяти не хватило, то возвращает `NULL`.

--------------------------------------------------------------------------------
### `realloc` (reallocation)

Функция `realloc` позволяет изменить размер уже выделенного блока памяти.

```c
int *tmp = realloc(p, 20 * sizeof(int));
if (tmp) {
    p = tmp;
}
```

- пытается изменить размер ранее выделенного блока;
- если после текущего блока есть память, то блок расширяется, иначе — пытается найти новый участок памяти;
- если памяти не хватило, то возвращает `NULL`, при этом старый блок остаётся валидным.

---

Тем не менее, динамическое выделение памяти выдаёт программисту дополнительную ответственность. После завершения работы функции, память автоматически не освобождается. Так, она останется висеть в куче до конца выполнения всей программы! Для того, чтобы не допустить такого поведения существует специальная функция:

### `free`

Функция `free` предназначена для освобождения динамической памяти. 

```c
int *p = malloc(5 * sizeof(int));
// ...code...
free(p);
```

---
## Ошибки при работе с динамической памятью

### 1. Memory Leak

- Если не использовать `free`, то можно *заслужить* `Memory Leak` — потеря указателя на динамически выделенную память без её освобождения. 
- Это может приводить к всё бОльшему и бОльшему потреблению памяти программой, что приведёт к аварийному завершению.

### 2. Double Free

- Если перестараться и использовать `free` несколько раз, то можно *заслужить* `Double Free` — попытка освобождения памяти, которая уже была освобождена.
- Это может повредить структуру данных кучи, что приведёт к аварийному завершению.

### 3. Dangling Pointers

- Если использовать указатель после использования `free`, то можно *заслужить* `Dangling Pointers` — указатели, хранящие старый адрес, на уже освобождённую память.
- Это может приводить к `Segmentation Fault`.

---
## Советы при работе с динамической памятью

Кажется, что советы будут очень просты — не натыкайтесь на `Memory Leak`, `Double Free` и `Dangling Pointers`. Для этого стоит занулять указатель после освобождения памяти:

```c
int *p = malloc(a_lot_of_memory);
// ...code...
free(p);
p = NULL;
```

Такой подход убивает сразу *трёх* зайцев! Освобождение памяти защищает от `Memory Leak`, а использование `NULL` позволяет избежать `Dangling Pointer`. Кроме того, освобождение `NULL`-указателя не является ошибкой, `free(NULL)` — абсолютно безопасное и безобидное действие, поэтому `Double Free` тоже не получить.
