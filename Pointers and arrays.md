## Что такое указатель

Указатель — это объект, который хранит адрес другого объекта или функции. Синтаксис указателя прост — надо поставить `*` между типом переменной и её названием.

```c
// Следующие записи эквивалентны:
int *ptr;
int* ptr;
int * ptr;
```

При этом тип, который будет написан совсем ничего не говорит о том, сколько памяти занимает этот указатель. В зависимости от архитектуры процессора указатель может занимать либо `4 байта`, либо `8 байтов`. А тип, написанный у указателя, лишь указывает на тип объекта, который этот самый указатель хранит.

С помощью указателей можно менять и сам объект, адрес которого мы храним. Для этого рассмотрим простой пример:

```c
char x = 'x';
char *ptr = &x;
*ptr = 'y';
```

Здесь:

- `char *ptr` — указатель на `char`;
- `&` — оператор взятия адреса;
- Если же теперь использовать `*ptr`, то это будет разыменование указателя — получение значения, хранящегося по адресу памяти, на который указывает указатель.
- Таким образом, `*ptr = 'y'` — это запись значения `y` по адресу памяти, который хранится в нашем указателе. Эта запись будет эквивалентна `x = 'y'` по смыслу. Но при этом в первом случае выполнится 2 операции — чтение памяти, где хранится указатель + запись в память, адрес которой хранился в указателе, а во втором случае всего 1 операция — запись в память. Хотя и этого может не произойти, потому что компилятор может оптимизировать количество инструкций первого случая до количества инструкций второго случая.

Также важно отметить о существовании указателя `void*`. Это некий обобщённый указатель, хранящий адрес на переменную любого типа. Очевидно, что такой указатель нельзя разыменовать, потому что мы не знаем, какой тип переменной он хранит, а тогда не знаем, какой размер данных хранится по адресу.

## Что такое `NULL`?

При динамическом выделении памяти часто встречается это значение, но зачем оно нужно? 

- `NULL` — специальный макрос, означающий пустой указатель, то есть указатель, который не хранит никакой адрес памяти.
- `NULL` гарантирует, что мы не обратимся по случайному/невалидному адресу.
- Попытка разыменовать такой указатель приведёт к ошибке `Segmentation Fault`.

## Арифметика указателей

Разобравшись в том, что такое указатель, стоит поговорить об арифметике указателей.
Предположим, что в указателе `ptr` хранится адрес `0x1000`. Чему тогда будет равно значение `ptr + 1`? Правильный ответ — неизвестно, но почему?

Дело в том, какой смысл несёт указатель — это адрес, по которому записан объект какого-то типа. Тогда абсолютно логично, что следующим адресом должен быть следующий объект этого же типа. Но разные объекты занимают разное число памяти, поэтому значение `ptr + 1` будет зависеть от типа объекта, адрес которого мы храним.

```c
char *char_ptr = (char *)0x1000;
int16_t *int16_t_ptr = (int16_t *)0x2000;
int32_t *int32_t_ptr = (int32_t *)0x3000;
int64_t *int64_t_ptr = (int64_t *)0x4000;

char_ptr++;    // 0x1001
int16_t_ptr++; // 0x2002
int32_t_ptr++; // 0x3004
int64_t_ptr++; // 0x4008
```

## Массивы

Массив — это непрерывная последовательность элементов одного типа. Самый простой пример массива длины 10:

```c
int arr[10];
```

При этом, как было сказано, массив является именно *непрерывной* последовательностью, поэтому и в памяти хранится непрерывно. Но тогда заметим связь с указателем!

Предположим, что в `int *ptr` хранится указатель на первый элемент массива, тогда `arr[i]` — это `i-ый` элемент массива, то есть нам надо сдвинуть указатель `ptr` на `i` позиций и разыменовать его! Получается, что `arr[i] = *(ptr + i)`. И на самом деле, даже записи `arr[i]` и `*(arr + i)` эквивалентны. Тем не менее, важно не попасть в заблуждение, что `arr` — это указатель — это неверно, `arr` — это константный адрес на первый элемент массива. Посмотрим на различия:

```c
int arr[10];
int *p = arr;
```

| **Характеристика**        | **int arr[10] (массив)**                                  | **int *p = arr (указатель)**                      |
| ------------------------- | --------------------------------------------------------- | ------------------------------------------------- |
| **Что это?**              | Имя непрерывного блока данных                             | Переменная, хранящая адрес                        |
| **Значение (адрес)**      | Фиксированный (константный) адрес первого элемента        | Адрес первого элемента                            |
| **Размер (`sizeof`)**     | Размер всех элементов (например, $10 \times 4 = 40$ байт) | Размер самого указателя (4 или 8 байт)            |
| **Присваивание**          | **Нельзя изменить**: `arr = ...` (ошибка компиляции)      | **Можно изменить**: `p = ...`                     |
| **Взятие адреса (`&`)**   | `&arr` возвращает указатель на массив (`int (*)[10]`)     | `&p` возвращает указатель на указатель (`int **`) |
| **Расположение в памяти** | Сам блок данных в стеке/куче                              | Ячейка памяти для переменной-указателя            |

### Инициализация массивов

Небольшой блок об инициализации массивов. По аналогии с переменными, если просто объявить `int a[10];`, то массив не будет инициализирован, но будет выделена память под элементы, хоть там и будет храниться мусор. 

```c
int a[10];              // неинициализированный массив (внутри мусор)
int b[10] = {0};        // все нули
int c[5] = {1, 2};      // остальные элементы станут нулями
```

Также для ситуации, когда нужно, например, указать значение только девятого элемента массива, можно использовать запись:

```c
// Следующие записи эквивалентны:
int d[10] = {0, 0, 0, 0, 0, 0, 0, 0, 5};
int d[10] = {[9] = 5}; // Designated Initializers
```

## Передача массивов в функции

Когда массив передают в функцию, параметр фактически становится указателем.

Эти объявления по смыслу эквивалентны:

```c
void f1(int a[10]);
void f2(int a[]);
void f3(int *a);
```

Именно поэтому внутри функции уже нельзя узнать исходную длину массива через `sizeof(a)`.

### Многомерные массивы

```c
int a[5][3];
```

Мы привыкли представлять двумерные массивы в виде таблицы, но в памяти таблицы не существует, а многомерный массив является непрерывной последовательностью элементов, как и обычный одномерный массив. В памяти они хранятся по правилу `Row-major order`, то есть построчно. Например, массив `z` хранился бы так:

```
Адрес:    0x1000 0x1004 0x1008 0x100C 0x1010 0x1014  ...
Элемент: |[0][0]|[0][1]|[0][2]|[1][0]|[1][1]|[1][2]  ...
```

Поэтому запись `a[i][j]` на самом деле означает `*(arr + (i * COLUMN_COUNT + j))`.

Из этого следует, что при передаче двумерного массива в функцию нужно знать размер всех измерений, кроме первого:

```c
// Следующие записи эквивалентны:
void f(int a[][3]);
void g(int (*a)[3]);
```

## VLA и указатели на массивы

В языке C мы можем объявить указатель, который ссылается не на один элемент, а на целый массив фиксированной (или переменной) длины. Синтаксис выглядит так:

```c
int (*ptr)[M]; // Указатель на массив из M элементов
```

Эта конструкция — отличный способ заставить компилятор думать, что перед ним двумерный массив, и использовать привычную индексацию `ptr[i][j]`, даже если память выделена в виде плоского одномерного блока.

## Строки

Просто так хранить строку в памяти не получится. Предположим, в памяти хранится поток символов, но как нам тогда понять, где закончилась наша строка? Для решения проблемы существует 2 основных подхода к хранению строки в памяти:
### 1. Переменная под длину строки

- Вычисление длины строки за `O(1)`.
- Ограничение по длине (переменная длины имеет физическое ограничение).
- Нужная дополнительная память для хранения строки в виде той самой переменной длины.

### 2. Специальный символ конца строки

- Вычисление длины строки за `O(length)`.
- Теряем 1 потенциальный символ алфавита, так как отдаём его под символ конца строки.
- Не нужна дополнительная память.

В C используется именно вторая реализация для хранения строки.

---
## Строки в C

Строка в C — это массив `char`, заканчивающийся нулевым байтом `'\0'`, называющимся нуль-терминалом.

```c
"abc"
```

На самом деле это последовательность:

```text
'a' 'b' 'c' '\0'
```

Из этого следуют важные свойства:

- `sizeof("abc") == 4`;
- `strlen("abc") == 3`;
- длина строки определяется не из метаданных, а поиском терминатора.
