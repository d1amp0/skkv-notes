--------------------------------------------------------------------------------

Qt — это C++-фреймворк для приложений. Его часто знают по GUI.

GUI расшифровывается как Graphical User Interface, то есть графический пользовательский интерфейс: окна, кнопки, поля ввода, меню, списки и другие элементы, с которыми пользователь взаимодействует глазами и мышью/клавиатурой.

Но Qt включает не только GUI: там есть строки, контейнеры, работа с файлами, сеть, многопоточность, event loop, метаобъектная система и многое другое.

Главная особенность Qt: это не "просто библиотека с классами". Qt добавляет поверх обычного C++ свою систему объектов и коммуникации между ними.

--------------------------------------------------------------------------------
## Общая архитектура Qt

Условно Qt-приложение можно представить так:

1. Есть обычный C++-код: классы, наследование, виртуальные функции, RAII.
2. Есть Qt-классы, многие из которых наследуются от `QObject`.
3. Есть event loop — цикл обработки событий.
4. Есть механизм сигналов и слотов, через который объекты сообщают друг другу о событиях.
5. Есть метаобъектная система Qt, для которой используется `Q_OBJECT` и `moc`.

То есть Qt не отменяет C++. Он добавляет к C++ свой слой.

--------------------------------------------------------------------------------
## Event loop

GUI-приложение обычно не работает как простая программа:

```cpp
int main() {
    do_step_1();
    do_step_2();
    return 0;
}
```

Оно большую часть времени ждет событий:

- пользователь нажал кнопку;
- пришли данные из сети;
- сработал таймер;
- окно нужно перерисовать.

Event loop — это цикл, который получает события и передает их нужным объектам.

В Qt этот цикл запускается примерно так:

```cpp
QApplication app(argc, argv);
return app.exec();
```

`app.exec()` запускает обработку событий. Без event loop сигналы, таймеры, GUI-события и многое другое не будут работать нормально.

## `QObject`

`QObject` — базовый класс для объектов, которым нужны возможности Qt-объектной системы. Он даёт объекту инфраструктуру Qt. 

Через `QObject` работают:

- имя объекта;
- дерево parent/child;
- события;
- метаобъектная информация;
- позже — сигналы и слоты.

Пример:

```cpp
class MyObject : public QObject {
public:
    MyObject(QObject *parent = nullptr);
};
```

Такой класс является обычным C++-классом, но еще и участвует в Qt-системе объектов.

--------------------------------------------------------------------------------
## Parent/child владение

В Qt у `QObject` может быть parent:

```cpp
QObject parent;
QObject child(&parent);
```

Идея: parent владеет своими children. Когда parent уничтожается, он уничтожает дочерние объекты.

Это похоже на автоматическое управление временем жизни объектов внутри дерева.

В GUI это удобно:

- окно владеет кнопками;
- виджет владеет дочерними виджетами;
- объект верхнего уровня при уничтожении чистит внутренние объекты.

Важно: parent/child — это не то же самое, что наследование. Наследование отвечает на вопрос "каким типом является объект", а parent/child — "кто владеет объектом во время выполнения".

## Метаобъектная система

Обычный C++ умеет классы, виртуальные функции, перегрузки и шаблоны. Но Qt нужны дополнительные возможности:

- узнать список сигналов;
- вызвать метод по имени;
- работать со свойствами;
- подключать сигнал к слоту;
- использовать introspection.

Для этого Qt использует метаобъектную систему.

Часть информации генерируется специальным инструментом `moc` — Meta-Object Compiler.

`moc` читает Qt-специфичные конструкции в заголовках и генерирует дополнительный C++-код.

--------------------------------------------------------------------------------
## `Q_OBJECT`

`Q_OBJECT` — макрос, который включает для класса метаобъектную систему Qt.

```cpp
class Counter : public QObject {
    Q_OBJECT

public:
    Counter(QObject *parent = nullptr);
};
```

Обычно `Q_OBJECT` нужен, если класс:

- объявляет свои сигналы;
- использует свои слоты в классическом Qt-стиле;
- объявляет свойства через `Q_PROPERTY`;
- должен полноценно участвовать в метаобъектной системе.

Если забыть `Q_OBJECT`, часто появляются странные ошибки линковки или неработающие сигналы/слоты. Это связано с тем, что `moc` не сгенерировал нужный дополнительный код.

--------------------------------------------------------------------------------
## Сигналы

Сигнал — это сообщение о событии.

Примеры событий:

- кнопка нажата;
- значение изменилось;
- загрузка завершилась;
- объект готов сообщить результат.

Сигнал объявляется в секции `signals`:

```cpp
class Counter : public QObject {
    Q_OBJECT

signals:
    void valueChanged(int value);
};
```

Сигнал обычно не реализуют руками. Мы только объявляем его, а техническую реализацию делает Qt через `moc`.

Чтобы испустить сигнал, пишут:

```cpp
emit valueChanged(10);
```

`emit` — макрос для читаемости. Он показывает человеку: здесь объект сообщает о событии.

--------------------------------------------------------------------------------
## Слоты

Слот — это функция, которую можно вызвать в ответ на сигнал.

```cpp
class Receiver : public QObject {
    Q_OBJECT

public slots:
    void onValueChanged(int value);
};
```

Если сигнал `valueChanged(int)` подключен к слоту `onValueChanged(int)`, то при испускании сигнала Qt вызовет этот слот.

В современном Qt слот не всегда обязан быть написан в секции `slots`; можно подключать обычные методы, лямбды и function objects. Но `slots` все еще часто встречается в учебниках и старом коде.

--------------------------------------------------------------------------------
## `connect`

`connect` связывает сигнал одного объекта со слотом другого объекта.

```cpp
connect(sender, &Counter::valueChanged,
        receiver, &Receiver::onValueChanged);
```

Смысл:

- `sender` — объект, который испускает сигнал;
- `&Counter::valueChanged` — какой именно сигнал;
- `receiver` — объект, который должен получить событие;
- `&Receiver::onValueChanged` — какой метод вызвать.

После такого подключения:

```cpp
emit valueChanged(10);
```

приведет к вызову:

```cpp
receiver->onValueChanged(10);
```

На самом деле Qt делает это через свою систему событий и метаобъектов, но по смыслу это связь "событие → реакция".

--------------------------------------------------------------------------------
## Совместимость сигнала и слота

Сигнал и слот должны быть совместимы по параметрам.

Например, так нормально:

```cpp
signals:
    void valueChanged(int value);

public slots:
    void onValueChanged(int value);
```

Слот принимает тот же `int`.

Слот может принимать меньше аргументов, если лишние аргументы сигнала ему не нужны:

```cpp
signals:
    void valueChanged(int value);

public slots:
    void update();
```

А вот если слот требует больше данных, чем сигнал передает, это уже проблема.

## Важные макросы Qt

### `Q_OBJECT`

Включает метаобъектную систему для класса.

### `signals`

Секция объявлений сигналов.

```cpp
signals:
    void finished();
```

### `slots`

Секция методов, которые могут использоваться как слоты.

```cpp
public slots:
    void start();
```

### `emit`

Пометка испускания сигнала.

```cpp
emit finished();
```

### `Q_PROPERTY`

Объявляет свойство для метаобъектной системы Qt:

```cpp
Q_PROPERTY(int value READ value WRITE setValue NOTIFY valueChanged)
```

Такое свойство может быть видно Qt-инструментам, QML и системе introspection.

--------------------------------------------------------------------------------
## Минимальный пример

```cpp
class Counter : public QObject {
    Q_OBJECT

    int value = 0;

public:
    void setValue(int newValue) {
        if (value == newValue) {
            return;
        }

        value = newValue;
        emit valueChanged(value);
    }

signals:
    void valueChanged(int value);
};

class Printer : public QObject {
    Q_OBJECT

public slots:
    void printValue(int value) {
        // печатаем value
    }
};
```

Подключение:

```cpp
connect(counter, &Counter::valueChanged,
        printer, &Printer::printValue);
```

Теперь `Counter` не знает, кто именно слушает его сигнал. Он просто сообщает: "значение изменилось". Это сильно уменьшает связанность между объектами.

--------------------------------------------------------------------------------
## Чем Qt отличается от обычного C++

Qt-код выглядит как C++, но часть конструкций обрабатывает не только C++-компилятор, но и Qt-инструменты.

Поэтому важны два уровня:

1. C++-уровень: классы, наследование, виртуальные функции, RAII.
2. Qt-уровень: `QObject`, parent/child, event loop, `Q_OBJECT`, сигналы, слоты, `moc`.

Если забыть про второй уровень, легко получить странные ошибки линковки или ситуацию, когда сигнал/слот не работает так, как ожидалось.
