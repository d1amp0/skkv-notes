--------------------------------------------------------------------------------

В C структура была просто набором полей. В C++ `struct` может иметь функции внутри, которые называются методами, а также операторы.

--------------------------------------------------------------------------------
## Методы структур

В C++ внутри `struct` можно объявлять не только поля, но и функции:

```cpp
struct S {
    int x;

    int f(int y) {
        return x + y;
    }
};

int main() {
    S s{10};
    int z = s.f(5); // 15
}
```

Такая функция называется методом. Она вызывается для конкретного объекта и имеет доступ к его полям. То есть `f` будет использовать в качестве `y` аргумент метода, а в качестве `x` — поле структуры.

Но как метод берёт этот самый `x`? На самом деле, у метода есть скрытый параметр `this` — указатель на объект, для которого вызван метод. Таким образом, обращение к `x` идёт с помощью указателя на сам объект.

```cpp
struct S {
    int x;

    int f(int y) {
        return this->x + y;
    }
};
```

Записи `x` и `this->x` здесь по смыслу совпадают. Обычно `this->` не пишут, если без него понятно.

А что будет, если имя поля и имя параметра совпадут?

```cpp
struct S {
    int x;

    int f(int x) {
        return x + 1;
    }
};
```

Внутри `f` имя `x` означает параметр функции, а не поле структуры. Более локальное имя "закрывает" поле с таким же именем.

Если нужно обратиться именно к полю, пишут `this->x`:

```cpp
struct S {
    int x;

    int f(int x) {
        return this->x + x;
    }
};
```

Здесь:

- `this->x` — поле объекта;
- `x` — параметр метода.

Поэтому одинаковые имена лучше не плодить без причины. Компилятор разберется, а человек потом будет грустить.

--------------------------------------------------------------------------------
## Определение метода вне структуры

Метод можно только объявить внутри структуры, а тело написать снаружи, некая аналогия с header-файлами:

```cpp
struct S {
    int x;
    int f(int y);
};

int S::f(int y) {
    return x + y;
}
```

`S::f` означает: функция `f`, которая принадлежит типу `S`.

Без `S::` компилятор бы увидел обычную свободную функцию `f`, а не метод структуры.

## `static`-методы и `static`-поля

Обычный метод вызывается для объекта и имеет скрытый указатель `this`.

`static`-метод не привязан к конкретному объекту, поэтому `this` у него нет:

```cpp
struct S {
    int x;

    static int answer() {
        return 42;
    }
};

int a = S::answer();
```

Такой метод можно вызвать без создания объекта. Смысл таких `static`-функций в том, чтобы функции, относящиеся по смыслу к конкретной структуре, лежали рядом с этой структурой или, например, можно сделать функцию-фабрику, которая создает объект:

```cpp
struct Point {
    int x;
    int y;

    static Point zero() {
        return Point{0, 0};
    }
};

Point p = Point::zero();
```

Так как у `static`-метода нет указателя `this`, то `static`-метод не может обратиться к обычному полю без объекта:

```cpp
struct S {
    int x;

    static int f() {
        return x; // нельзя: непонятно, у какого объекта брать x
    }
};
```

`static`-поле тоже общее для всего типа, а не отдельное для каждого объекта:

```cpp
struct S {
    static int counter;

    S() {
        counter++;
    }
};

int S::counter = 0;

S a;
S b;
// S::counter теперь 2
```

Обычное поле лежит внутри каждого объекта:

```cpp
struct S {
    int x;
};

S a;
S b;

a.x = 1;
b.x = 2;
```

У `a` свой `x`, у `b` свой `x`.

А `static`-поле одно на весь тип:

```cpp
S::counter = 10;
```

К нему обычно обращаются через имя типа: `S::counter`. Можно встретить и `a.counter`, но это хуже читается, потому что создает ощущение, будто поле лежит именно в объекте `a`.

В старом стиле C++ объявление `static`-поля внутри структуры не выделяет под него память. Это только объявление: "такое поле существует".

```cpp
struct S {
    static int counter; // объявление
};

int S::counter = 0; // определение, здесь реально появляется объект counter
```

Если забыть внешнее определение и начать использовать `S::counter`, можно получить ошибку линковки.

## `public`, `private`, `protected`

Уровни доступа управляют тем, откуда можно обращаться к полям и методам.

```cpp
struct S {
public:
    int x;

private:
    int secret;
};

int main() {
    S s;
    s.x = 10;      // можно: x public
    s.secret = 20; // нельзя: secret private
}
```

То есть видимость означает можно ли обратиться к имени снаружи структуры. Таким образом, к полю `x` можно обратиться, присвоить значение, а вот к полю `secret` — нет!

```cpp
s.secret = 20; // ошибка компиляции
```

Зато и к `public`, и к `private` внутри методов этой же структуры обращаться можно:

```cpp
struct S {
private:
    int secret;

public:
    void set_secret(int value) {
        secret = value; // можно
    }

    int get_secret() {
        return secret; // можно
    }
};
```

- `public` — к имени можно обращаться снаружи объекта;
- `private` — к имени можно обращаться только из методов этого же типа. Еще есть специальное разрешение `friend`, но до него дойдем ниже;
- `protected` — пока просто запомним, что такой уровень есть. Он связан с наследованием, поэтому нормально разберем его позже в [[C++ inheritance#`protected`|наследовании]].

Обычно наружу оставляют только то, что является интерфейсом типа. Детали реализации прячут в `private`.

## `struct` и `class`

В C++ `struct` и `class` почти одинаковые. Главное отличие — видимость по умолчанию:

- в `struct` все по умолчанию `public`;
- в `class` все по умолчанию `private`.

```cpp
struct A {
    int x; // public
};

class B {
    int x; // private
};
```

То есть эта структура:

```cpp
struct A {
    int x;
};
```

по видимости примерно такая:

```cpp
struct A {
public:
    int x;
};
```

А этот класс:

```cpp
class B {
    int x;
};
```

по видимости примерно такой:

```cpp
class B {
private:
    int x;
};
```

Поэтому `struct` часто используют для простых "пакетов данных", а `class` — когда важна инкапсуляция. Но технически методы, конструкторы и операторы можно писать и там, и там.

## `const`-методы

Метод можно пометить как `const`:

```cpp
struct S {
    int x;

    int get() const {
        return x;
    }
};
```

Такой метод обещает не менять объект.

```cpp
const S s{10};
s.get(); // можно
```

Фактически `const` после имени метода означает, что скрытый указатель `this` указывает на константный объект. Поэтому внутри такого метода нельзя менять обычные поля:

```cpp
struct S {
    int x;

    void bad() const {
        x = 10; // нельзя: const-метод обещал не менять объект
    }
};
```

Такой метод не может быть `const`, если его нормальный смысл — изменить объект:

```cpp
struct Counter {
    int value;

    void inc() const {
        value++; // нельзя
    }
};
```

Правильно:

```cpp
struct Counter {
    int value;

    void inc() {
        value++;
    }
};
```

А вот метод, который только читает состояние, как раз должен быть `const`:

```cpp
struct Counter {
    int value;

    int get() const {
        return value;
    }
};
```

Если метод не `const`, то для `const`-объекта его вызвать нельзя:

```cpp
struct S {
    int x;
    int get() { return x; }
};

const S s{10};
s.get(); // ошибка
```

У одного класса могут быть две версии метода:

```cpp
struct S {
    int x;
    int y;

    int f() { return x; }
    int f() const { return y; }
};
```

Если объект не `const`, выбирается неконстантная версия. Если объект `const`, выбирается `const`-версия.

```cpp
S a{1, 2};
const S b{1, 2};

a.f(); // вернет x
b.f(); // вернет y
```

--------------------------------------------------------------------------------
## `mutable`

`mutable` разрешает менять поле даже внутри `const`-метода или у `const`-объекта:

```cpp
struct S {
    int x;
    mutable int cached;

    void f() const {
        cached = 10; // можно
        // x = 20;   // нельзя
    }
};
```

Это бывает нужно для кэшей, счетчиков обращений и других служебных деталей, которые не меняют логический смысл объекта.

Но да, `mutable` немного ломает простую идею `const`. Поэтому пихать его везде — плохая мысль.

## Перегрузка функций

В C нельзя иметь две функции с одинаковым именем. В C++ можно, если отличаются параметры:

```cpp
int abs(int x);
double abs(double x);
```

Компилятор выбирает нужную функцию по типам аргументов. Это называется перегрузкой функций.

Возвращаемый тип сам по себе для перегрузки не подходит:

```cpp
int f();
double f(); // нельзя: отличаются только возвращаемым типом
```

Почему нельзя? Потому что вызов:

```cpp
f();
```

не дает компилятору достаточно информации, какую функцию выбрать. Да, иногда результат потом присваивается в переменную:

```cpp
double x = f();
```

Но правила перегрузки не должны зависеть от того, куда потом пошел результат. Поэтому перегрузка определяется по параметрам функции, а не по возвращаемому типу.

А вот одинаковое имя и одинаковый возвращаемый тип, но разные типы аргументов — можно:

```cpp
int f(int x);
int f(double x);

int a = f(5);   // f(int)
int b = f(2.5); // f(double)
```

Здесь обе функции возвращают `int`, но параметры разные, поэтому перегрузка корректная.

Из-за перегрузок в C++ появляется name mangling: реальное имя функции в объектном файле кодирует не только имя, но и типы параметров. Поэтому для совместимости с C иногда нужен `extern "C"` — см. [[Header files#Совместимость с C++ (`extern "C"`)|заголовочные файлы]].

## Перегрузка операторов

Пусть есть двумерный вектор. Хотелось бы написать для него сложение. Давайте сделаем это:

```cpp
struct V {
    int x;
    int y;

    V add(V b) {
        return V{x + b.x, y + b.y};
    }
};
```

Тогда приходится писать:

```cpp
V k = m.add(n);
```

Это работает, но выглядит не как сложение. В C++ можно перегрузить оператор:

```cpp
struct V {
    int x;
    int y;

    V operator+(V b) {
        return V{x + b.x, y + b.y};
    }
};

V k = m + n;
```

Это первая рабочая версия. Выражение:

```cpp
k = m + n;
```

для такого метода примерно превращается в:

```cpp
k = m.operator+(n);
```

То есть левый операнд `m` становится объектом, для которого вызвали метод, а правый операнд `n` передается как аргумент `b`.

Но у этой реализации есть две проблемы.

Первая проблема — лишнее копирование. Параметр `V b` передается по значению, значит `n` копируется:

```cpp
V operator+(V b)
```

Если `V` маленький, это почти неважно. Но если объект большой, копирование может быть дорогим. При этом менять `b` мы не собираемся. Поэтому лучше принять аргумент по константной ссылке:

```cpp
V operator+(const V &b) {
    return V{x + b.x, y + b.y};
}
```

Почему именно `const V &`, а не просто `V &`?

Ссылка без `const` означает: функция может менять переданный объект.

```cpp
V operator+(V &b) {
    b.x = 100; // технически можно
    return V{x + b.x, y + b.y};
}
```

Для сложения это странно. Когда мы пишем `m + n`, мы не ожидаем, что `n` внезапно изменится. Поэтому правый аргумент надо принять как `const V &`: без копирования, но с обещанием не менять объект.

Есть еще один практический плюс: `const V&` может принимать `const`-объекты.

```cpp
const V n{3, 4};
m + n; // с V& нельзя, с const V& можно
```

Теперь правый операнд не копируется, а метод обещает его не менять.

Вторая проблема — сам метод не помечен как `const`. Значит, его нельзя вызвать у `const`-объекта:

```cpp
const V m{1, 2};
const V n{3, 4};

V k = m + n; // не получится, если operator+ не const
```

Но сложение векторов по смыслу не должно менять левый операнд. Значит, метод тоже надо сделать `const`:

```cpp
struct V {
    int x;
    int y;

    V operator+(const V &b) const {
        return V{x + b.x, y + b.y};
    }
};
```

Итоговая форма:

- `const V &b` — чтобы не копировать правый аргумент;
- `const` после метода — чтобы можно было складывать `const`-объекты;
- результат возвращается по значению, потому что создается новый вектор.

## Оператор как метод и как внешняя функция

А теперь мы по какой-то причине захотели научить наш вектор складываться с обычным числом. Зная о перегрузке операторов, мы можем написать такой код:

```cpp
struct V {
    int x;
    int y;

    V operator+(int z) const {
        return V{x + z, y + z};
    }
};

V a = v + 5;
```

Но такая форма не позволит написать `5 + v`, потому что слева стоит `int`, а у `int` нельзя дописать метод.

Поэтому в таких случаях используют внешнюю функцию:

```cpp
V operator+(int z, const V &v) {
    return v + z;
}
```

## `friend`

Теперь можно нормально понять, зачем нужен `friend`.

Пусть поля класса приватны:

```cpp
class V {
private:
    int x;
    int y;

public:
    V(int x, int y) : x(x), y(y) {}

    V operator+(int z) const {
        return V{x + z, y + z};
    }
};
```

Метод `operator+(int)` имеет доступ к `x` и `y`, потому что он внутри класса. Но внешняя функция уже не внутри класса:

```cpp
V operator+(int z, const V &v) {
    return V{v.x + z, v.y + z}; // нельзя: x и y private
}
```

Чтобы разрешить конкретной внешней функции доступ к закрытым полям, ее объявляют другом:

```cpp
class V {
private:
    int x;
    int y;

public:
    V(int x, int y) : x(x), y(y) {}

    friend V operator+(int z, const V &v);
};

V operator+(int z, const V &v) {
    return V{v.x + z, v.y + z}; // теперь можно
}
```

`friend` — это точечное разрешение доступа. Оно не делает функцию методом класса. Функция все еще внешняя, просто ей разрешили смотреть в `private`.

Важно:

- дружба не симметрична;
- дружба не транзитивна;
- дружба с одной перегрузкой функции не означает дружбу со всеми перегрузками.

Пока достаточно понимать: это способ аккуратно открыть закрытые поля конкретной внешней функции.

## `operator+=`

Оператор `+=` отличается от `+` по смыслу.

Обычное сложение:

```cpp
k = m + n;
```

не должно менять `m` и `n`. Оно создает новый результат.

А `+=` специально существует как операция "прибавить к самому себе":

```cpp
m += n;
```

После этой строки меняется `m`.

Самая простая реализация могла бы быть такой:

```cpp
struct V {
    int x;
    int y;

    void operator+=(const V &b) {
        x += b.x;
        y += b.y;
    }
};
```

И это даже позволит написать:

```cpp
m += n;
```

Но у операторов в C++ есть важная идея: выражение тоже имеет значение. Например, для обычных `int` можно писать:

```cpp
int a = 1;
int b = 2;
int c = 3;

a += b += c;
```

Разберем справа налево:

```cpp
b += c; // b стал 5, результат выражения — сам b
a += b; // a стал 6
```

Чтобы такое работало для нашего `V`, `operator+=` должен не просто менять объект, но и возвращать ссылку на измененный объект.

```cpp
struct V {
    int x;
    int y;

    V &operator+=(const V &b) {
        x += b.x;
        y += b.y;
        return *this;
    }
};
```

Почему именно `V&`, а не `V`?

Если вернуть `V` по значению, создастся копия. А результат `+=` по смыслу должен быть тем же самым левым объектом, который мы изменили.

```cpp
V &operator+=(const V &b)
```

означает: вернуть ссылку на текущий объект.

Что такое текущий объект? Это `*this`.

```cpp
return *this;
```

Если вызвали:

```cpp
m += n;
```

то внутри метода:

- `this` — указатель на `m`;
- `*this` — сам объект `m`;
- `b` — ссылка на `n`.

Теперь цепочка работает:

```cpp
a += b += c;
```

Сначала выполнится `b += c`, он изменит `b` и вернет ссылку на `b`. Потом `a += ...` получит уже измененный `b`.

Именно поэтому каноническая форма такая:

```cpp
V &operator+=(const V &b) {
    x += b.x;
    y += b.y;
    return *this;
}
```

## Префиксный и постфиксный `++`

Для `++` есть две формы:

```cpp
struct Counter {
    int x;

    Counter &operator++() {
        ++x;
        return *this;
    }

    Counter operator++(int) {
        Counter old = *this;
        ++x;
        return old;
    }
};
```

Фиктивный параметр `int` нужен только для различения постфиксной формы.

- `++c` — префиксный оператор;
- `c++` — постфиксный оператор.

Префиксный `++c` сначала меняет объект, а потом возвращает уже измененный объект. Поэтому он может вернуть ссылку:

```cpp
Counter &operator++() {
    ++x;
    return *this; // возвращаем сам текущий объект
}
```

А постфиксный `c++` по смыслу работает иначе: он должен изменить `c`, но результатом выражения должно быть старое значение.

```cpp
Counter c{5};
Counter old = c++; // old.x = 5, c.x = 6
```

Чтобы вернуть старое значение, его нужно сначала сохранить:

```cpp
Counter operator++(int) {
    Counter old = *this; // копия старого состояния
    ++x;                 // меняем текущий объект
    return old;          // возвращаем старое значение
}
```

Почему здесь возвращается не `Counter&`, а просто `Counter`?

Потому что старое значение — это отдельная временная копия `old`. Нельзя вернуть ссылку на локальную переменную `old`: после выхода из функции она уничтожится, и ссылка станет висячей.

```cpp
Counter &operator++(int) {
    Counter old = *this;
    ++x;
    return old; // нельзя: ссылка на локальную переменную
}
```

Вернуть ссылку на `*this` тоже было бы неверно по смыслу:

```cpp
Counter &operator++(int) {
    ++x;
    return *this; // это вернуло бы новое значение, а постфиксный ++ должен вернуть старое
}
```

Именно поэтому постфиксный оператор обычно дороже префиксного: ему приходится создавать копию старого состояния.

--------------------------------------------------------------------------------
## Что нельзя или не стоит перегружать

Нельзя перегрузить оператор только для встроенных типов:

```cpp
int operator+(int a, int b); // нельзя
```

Хотя бы один аргумент должен быть пользовательского типа.

Также не все операторы можно перегружать свободно. Например, оператор присваивания `operator=` должен быть методом класса.

Отдельная опасность: перегрузка `&&`, `||` и `,` не сохраняет привычное short-circuit поведение как у встроенных операторов. Поэтому такие перегрузки легко делают код хуже, чем был.
