## Назначение заголовочных файлов и директива `#include`

В `.h` файлы обычно помещают:

- прототипы функций;
- объявления типов (`struct`, `enum`, `typedef`);
- макросы;
- внешние объявления объектов (`extern`);
- небольшие `static inline` функции.

**Идея проста:** реализация живет в `.c`, а интерфейс — в `.h`.

Директива `#include` заменяет строку с ней на полное содержимое указанного файла. Существует два типа:

- `#include <file.h>` — поиск файла осуществляется в стандартных системных директориях компилятора.
- `#include "file.h"` — поиск начинается с текущей (локальной) директории проекта, а затем переходит к системным.

## Макросы и директива `#define`

Директива `#define` — это инструмент препроцессора для **текстовой подстановки** до начала компиляции. Макросы не являются типобезопасными переменными или функциями. Ещё раз, надо понять, что макрос — это просто ЗАМЕНА ТЕКСТА.

В контексте заголовков `#define` используется для:

1. **Символьных констант:**

```
	#define BUFFER_SIZE 1024
	#define PI 3.14159
```

2. **Параметризованных макросов (макрофункций):**

```
	#define MAX(a, b) ((a) > (b) ? (a) : (b))
	#define SQUARE(x) ((x) * (x))
```

Может появиться вопрос, почему тут аргументы этих макрофункций используются в `()`?
Дело в том, что их отсутствие может нарушить ожидаемый порядок вычислений. Предположим, что мы бы не использовали скобки:

```
#define SQUARE(x) (x * x)

Теперь при использовании SQUARE(2 + 3) получим:
2 + 3 * 2 + 3 = 11 — явно не тот результат, что мы ожидали получить
```

## Директивы условной компиляции

Условная компиляция позволяет включать или исключать фрагменты кода в зависимости от условий препроцессора:

- `#ifdef МАКРОС` — проверяет, объявлен ли макрос.
- `#ifndef МАКРОС` — проверяет, **не** объявлен ли макрос.
- `#if УСЛОВИЕ` — проверяет константное выражение.
- `#elif УСЛОВИЕ` — аналог `else if` для препроцессора.
- `#else` — выполняется, если предыдущие условия не сработали.
- `#endif` — завершает блок условной компиляции.

### Пример адаптации fseek для платформ

```
#ifndef _WIN32
    // Для POSIX-совместимых систем (Linux, macOS)
    #define fseeko fseeko
#else
    // Для Windows (MSVC)
    #define fseeko _fseeki64
#endif
```

## Защита от повторного включения (Include guards)

Предположим простую ситуацию. В `A.h` инклудится `B.h`, а в файле `main.c` инклудится и `A.h`, и `B.h`, но тогда выходит, что `B.h` инклудился 2 раза! Для того, чтобы избежать этот сценарий используют классическую схему:

```
#ifndef HEADER_FILE_H
#define HEADER_FILE_H

// Содержимое файла

#endif
```

Более современная альтернатива — `#pragma once`, которая ставится в начале файла (хотя она не является стандартом, сейчас она есть во всех популярных компиляторах).

## Совместимость с C++ (`extern "C"`)

Вот и первое упоминание C++. Предположим, что хочется использовать в C++ функцию, написанную на C. К сожалению, просто так использовать её не получится, так как в C++ существует **name mangling**, из-за чего компоновщик C++ не может найти функции, скомпилированные компилятором C.

Для решения этой проблемы используется блок `extern "C"`, который указывает, что код внутри должен использовать соглашения о вызовах языка C.

В заголовочном файле это оформляется так:

```
#ifdef __cplusplus
extern "C" {
#endif

float abs(float x);

#ifdef __cplusplus
}
#endif
```

## Встраивание ресурсов

### `#embed` (начиная с C23)

`#embed` используется для встраивания внешних данных (бинарных или текстовых) в программу на этапе трансляции:


```c
const unsigned char my_data[] = {
    #embed "data.bin"
};
```

- **Удобство:** не нужно использовать сторонние утилиты для превращения файлов в C-массивы.
- **Ограничение:** зависит от компилятора и поддерживается в новых версиях стандарта.
