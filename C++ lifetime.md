--------------------------------------------------------------------------------

В C объект часто воспринимается как кусок памяти нужного размера. В C++ этого уже недостаточно: у объекта есть время жизни, конструктор, деструктор, копирование, присваивание и иногда неявные преобразования.

--------------------------------------------------------------------------------
## Конструкторы

Конструктор — это специальный метод, который вызывается при создании объекта.

```cpp
struct V {
    int x;
    int y;

    V() {
        x = 1;
        y = 2;
    }
};

V v; // вызывается V()
```

Имя конструктора совпадает с именем типа, а возвращаемого типа у него нет.

Если в структуре не написать ни одного конструктора, компилятор сам объявит конструктор по умолчанию. Для такой простой структуры он будет делать примерно ничего:

```cpp
struct S {
    int x;
};

S s; // x может содержать мусор
```

Здесь `S s;` создает объект `S`, но поле `x` не получает значение `0` автоматически. Оно остается неинициализированным, как обычная локальная переменная `int x;` в C.

Если нужен ноль, его надо явно указать:

```cpp
S s{}; // x будет 0
```

## Если написать свой конструктор

Если у типа есть конструктор с параметром:

```cpp
struct V {
    int x;
    int y;

    V(int z) {
        x = z;
        y = z;
    }
};
```

То `V n(4);` работает, а `V m;` не скомпилируется:

```cpp
V n(4); // можно: есть V(int)
V m;    // ошибка: нет конструктора V()
```

Причина конкретная: запись `V m;` требует конструктор без аргументов, а мы его не написали. Как только у типа появился пользовательский конструктор `V(int)`, компилятор уже не добавляет за нас простой `V()`.

Можно написать оба:

```cpp
struct V {
    int x;
    int y;

    V() {
        x = 0;
        y = 0;
    }

    V(int z) {
        x = z;
        y = z;
    }
};
```

Или использовать аргумент по умолчанию:

```cpp
struct V {
    int x;
    int y;

    V(int z = 0) {
        x = z;
        y = z;
    }
};
```

## Список инициализации

В C++ есть специальный синтаксис инициализации полей:

```cpp
struct V {
    const int x;
    const int y;

    V(int z) : x(z), y(z) {}
};
```

Это не просто красивая запись. Некоторые поля нельзя сначала создать, а потом присвоить:

- `const`-поля;
- ссылки;
- объекты классов без конструктора по умолчанию.

Плохо:

```cpp
struct S {
    const int x;

    S(int z) {
        x = z; // нельзя: const-поле уже должно быть инициализировано
    }
};
```

Хорошо:

```cpp
struct S {
    const int x;

    S(int z) : x(z) {}
};
```

Порядок инициализации полей определяется не порядком в списке инициализации, а порядком объявления полей в структуре.

```cpp
struct S {
    int a;
    int b;

    S() : b(2), a(1) {} // реально сначала a, потом b
};
```

Поэтому список лучше писать в том же порядке, что и поля. Иначе можно очень красиво наступить на странный баг.

Список инициализации стоит использовать не только тогда, когда без него нельзя. В C++ это обычно предпочтительный способ инициализировать поля.

```cpp
struct Point {
    int x;
    int y;

    Point(int x, int y) : x(x), y(y) {}
};
```

Почему так лучше?

- Поле сразу создается с нужным значением.
- Для сложных объектов это избегает схемы "сначала создать как-нибудь, потом присвоить".
- Один и тот же стиль работает для обычных полей, `const`-полей, ссылок и полей-классов.

Тело конструктора лучше оставлять для действий, которые нельзя выразить простой инициализацией.

## `explicit`

Конструктор с одним аргументом может использоваться для неявного преобразования:

```cpp
struct S {
    int x;

    S(int value) : x(value) {}
};

S s = 5; // можно: int неявно превращается в S
```

Более реальный пример:

```cpp
struct Meter {
    int value;

    Meter(int value) : value(value) {}
};

void print_distance(Meter m) {
    // печатаем расстояние
}

print_distance(5); // 5 неявно превращается в Meter{5}
```

С одной стороны, удобно. С другой стороны, функция вроде бы принимает `Meter`, а мы передали обычный `int`. Если такое преобразование случайное, код становится слишком неявным.

Чтобы запретить неявное преобразование, используют `explicit`:

```cpp
struct S {
    int x;

    explicit S(int value) : x(value) {}
};

S a(5);  // можно
S b{5};  // можно
S c = 5; // нельзя
```

С примером функции:

```cpp
struct Meter {
    int value;

    explicit Meter(int value) : value(value) {}
};

void print_distance(Meter m) {}

print_distance(5);        // нельзя
print_distance(Meter{5}); // можно: явно создали Meter
```

Если конструктор должен работать только там, где программист явно попросил создать объект, лучше ставить `explicit`.

## Операторы преобразования типа

Можно определить преобразование объекта к другому типу:

```cpp
struct S {
    int k;

    S(int x) : k(x) {}

    operator int() const {
        return k;
    }
};

S s(10);
int x = s; // вызывается operator int()
```

Это мощная штука, но она может делать код слишком неявным. Если объект внезапно превращается в `int`, компилятор может выбрать не тот overload, который человек ожидал.

В современном C++ такие операторы тоже часто делают `explicit`, если нет очень веской причины разрешать неявность.

## Деструкторы

Деструктор вызывается перед уничтожением объекта:

```cpp
struct S {
    ~S() {
        // освобождение ресурсов
    }
};
```

Имя деструктора — `~` плюс имя типа. У деструктора:

- нет возвращаемого типа;
- нет параметров;
- не может быть перегрузок.

Если деструктор не написать, компилятор сгенерирует деструктор, который ничего особенного не делает, кроме уничтожения полей.

Деструктор особенно важен, когда объект владеет ресурсом:

- динамической памятью;
- файлом;
- сетевым соединением;
- mutex-ом;
- любым ресурсом, который нужно вернуть системе.

#### Деструктор - обязательно noexcept!
Все деструкторы по умолчанию - `noexcept` (и это не меняется)

Это следует из поведения при бросании исключений: если вдруг при раскрутке стека бросится ещё одно исключение, непонятно, что делать дальше

## RAII

RAII расшифровывается как Resource Acquisition Is Initialization — "захват ресурса есть инициализация".

Идея такая: ресурс должен быть привязан к объекту.

Объект создался — ресурс захвачен. Объект умер — ресурс освобожден.

```cpp
#include <cstdio>

struct File {
    std::FILE *f;

    File(const char *name) {
        f = std::fopen(name, "r");
    }

    ~File() {
        if (f != nullptr) {
            std::fclose(f);
        }
    }
};
```

Теперь при выходе из области видимости деструктор вызовется автоматически:

```cpp
void f() {
    File file("input.txt");
} // здесь автоматически вызовется ~File()
```

Именно поэтому C++ так любит объекты: они позволяют не забывать освобождение ресурса вручную в каждом выходе из функции.

В примере выше ресурс — открытый файл. В следующем разделе про динамическую память будет такой же смысл для `new/delete`: объект владеет памятью, а деструктор ее освобождает.

## Копирование объектов

Если объект передается по значению, возвращается по значению или явно копируется, используется конструктор копирования.

```cpp
struct S {
    int x;
};

void f(S a) {}

int main() {
    S s{10};
    f(s); // создается копия
}
```

Если конструктор копирования не написать, компилятор сгенерирует его сам. Стандартная версия копирует поля по одному.

Для простых типов это нормально. Для типов, владеющих ресурсами, это может быть катастрофа.

```cpp
#include <cstdlib>
#include <cstring>

struct BadString {
    char *p;

    BadString(const char *s) {
        p = (char *)std::malloc(std::strlen(s) + 1);
        std::strcpy(p, s);
    }

    ~BadString() {
        std::free(p);
    }
};
```

Если такой объект скопировать стандартным копированием, скопируется только указатель. В итоге два объекта будут думать, что владеют одной и той же памятью. Потом оба вызовут `free`. Получаем double free и заслуженный хаос.

## Конструктор копирования

Конструктор копирования обычно выглядит так:

```cpp
struct S {
    S(const S &other) {
        // создать новый объект как копию other
    }
};
```

Параметр почти всегда `const S&`, чтобы:

- не копировать объект еще раз;
- разрешить копирование `const`-объектов.

Для строки с владением памятью нужна глубокая копия:

```cpp
#include <cstdlib>
#include <cstring>

struct String {
    char *p;

    String(const char *s) {
        p = (char *)std::malloc(std::strlen(s) + 1);
        std::strcpy(p, s);
    }

    String(const String &other) {
        p = (char *)std::malloc(std::strlen(other.p) + 1);
        std::strcpy(p, other.p);
    }

    ~String() {
        std::free(p);
    }
};
```

Теперь у каждой копии свой буфер.

## Оператор присваивания

Копирование при создании и присваивание уже существующему объекту — разные операции.

```cpp
String a("abc");
String b = a; // конструктор копирования

String c("xxx");
c = a;        // оператор присваивания
```

Оператор присваивания обычно возвращает ссылку на текущий объект:

```cpp
struct S {
    S &operator=(const S &other) {
        if (this != &other) {
            // освободить старые ресурсы
            // скопировать новые
        }
        return *this;
    }
};
```

Проверка `this != &other` защищает от самоприсваивания:

```cpp
a = a;
```

Не всегда она строго нужна, но если внутри есть освобождение памяти, без нее можно сначала удалить собственные данные, а потом пытаться копировать из уже удаленного места. Не лучший план.

--------------------------------------------------------------------------------
## Правило трех

Если тип вручную определяет хотя бы одну из трех операций:

- деструктор;
- конструктор копирования;
- оператор копирующего присваивания;

то почти наверняка нужно подумать обо всех трех.

Это называется правилом трех.

Причина простая: если объект владеет ресурсом, то нужно корректно:

- освободить ресурс;
- создать независимую копию;
- присвоить один объект другому без утечек и double free.

--------------------------------------------------------------------------------
## `= delete`

Если копирование или присваивание нужно запретить, можно удалить соответствующую функцию:

```cpp
struct S {
    S() = default;

    S(const S &) = delete;
    S &operator=(const S &) = delete;
};
```

Теперь такие операции не скомпилируются:

```cpp
S a;
S b = a; // ошибка
```

Это лучше, чем оставить случайное копирование, которое потом развалит владение ресурсом.

--------------------------------------------------------------------------------
## `= default`

Если нужно явно попросить компилятор сгенерировать стандартную версию функции, используют `= default`:

```cpp
struct S {
    S() = default;
    ~S() = default;
};
```

Это полезно, когда хочется явно показать намерение: да, стандартное поведение подходит.
