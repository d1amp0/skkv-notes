--------------------------------------------------------------------------------

C++ вырос из C, поэтому много старых идей здесь остались: компиляция по файлам, указатели, память, UB, заголовочные файлы. Но поверх этого появились новые механизмы: ссылки, перегрузки, методы, конструкторы, классы, пространства имен и т.д.

--------------------------------------------------------------------------------
## `std::`

В C++ многие стандартные функции, типы и объекты пишутся с префиксом `std::`.

```cpp
std::printf("hello\n");
std::malloc(10);
```

Пока можно воспринимать `std::` как часть имени стандартной C++-штуки. Полный смысл будет позже в разделе про [[C++ modern features#Namespace|namespace]].

Например, в C мы писали:

```c
printf("hello\n");
```

А в C++ часто пишут:

```cpp
std::printf("hello\n");
```

Это связано с тем, что стандартная библиотека C++ живет в пространстве имен `std`.

Если в примерах ниже встретится `std::bad_alloc`, `std::malloc`, `std::free`, `std::vector` и похожие имена, сейчас важно только одно: это имена из стандартной библиотеки C++. Подробно разберемся с этим в namespaces.

## Аргументы по умолчанию

В C++ у функции можно указать значения параметров по умолчанию:

```cpp
int f(int a, int b = 1) {
    return a + b;
}

int x = f(10);     // b подставится как 1
int y = f(10, 5);  // b будет 5
```

Но есть важное правило: если у какого-то параметра появилось значение по умолчанию, то все параметры правее тоже должны иметь значения по умолчанию.

```cpp
int f(int a = 0, int b); // нельзя
int g(int x, int y = 2, int z = 3); // можно
```

Почему так? Потому что вызов должен быть однозначным. Если разрешить "дырки" в аргументах по умолчанию, компилятору пришлось бы гадать, какой аргумент пользователь пропустил.

## Передача по значению, указателю и ссылке

В C уже были два основных способа передачи данных:

- по значению;
- по указателю.

Передача по значению копирует объект:

```cpp
void inc(int x) {
    x = x + 1;
}

int main() {
    int a = 5;
    inc(a);
    // a все еще 5
}
```

Передача по указателю передает адрес объекта:

```cpp
void inc(int *x) {
    *x = *x + 1;
}

int main() {
    int a = 5;
    inc(&a);
    // a теперь 6
}
```

В C++ появился третий вариант — передача по ссылке:

```cpp
void inc(int &x) {
    x = x + 1;
}

int main() {
    int a = 5;
    inc(a);
    // a теперь 6
}
```

Ссылка похожа на "другое имя" для уже существующего объекта. Внутри `inc` переменная `x` не является копией `a`; она ссылается на тот же объект.

## Ссылки

Синтаксис ссылки использует `&`:

```cpp
int a = 5;
int &b = a;

b = 10; // меняет a
```

У амперсанда в C/C++ несколько смыслов:

- бинарная побитовая операция `a & b`;
- взятие адреса `&a`;
- объявление ссылки `int &b = a`.

Это не одно и то же. Смысл зависит от контекста.

Ссылка обязана быть инициализирована сразу:

```cpp
int &x; // нельзя
```

И после инициализации ее нельзя "перепривязать" к другому объекту:

```cpp
int a = 1;
int b = 2;

int &r = a;
r = b; // это не перепривязка, это a = b
```

## `nullptr`

В C для пустого указателя обычно использовали `NULL`.

```c
int *p = NULL;
```

В C++ появился `nullptr` — специальное значение, которое означает именно нулевой указатель.

```cpp
int *p = nullptr;
char *s = nullptr;
```

То есть `nullptr` — это не адрес какого-то объекта. Это значение указателя, которое говорит: "сейчас этот указатель никуда не указывает".

Разыменовывать такой указатель нельзя:

```cpp
int *p = nullptr;
*p = 10; // UB
```

Зачем понадобился `nullptr`, если уже был `NULL`? Проблема в том, что `NULL` исторически часто является просто нулем. А в C++ есть перегрузка функций, и обычный ноль может выбрать не ту функцию:

```cpp
void f(int);
void f(char *);

f(0);       // вызов f(int)
f(NULL);    // тоже может выбрать f(int)
f(nullptr); // выбирается f(char *)
```

Поэтому в C++ лучше писать `nullptr`, а не `NULL`.

## Ссылка — почти указатель под капотом, но не указатель по смыслу языка

На уровне реализации ссылка часто устроена почти как указатель: компилятору все равно нужно как-то помнить, к какому объекту обращается ссылка, и обычно для этого используется адрес.

Но в самом языке ссылка описывается не как отдельный объект-указатель, а как другое имя уже существующего объекта.

```cpp
int a = 5;
int *p = &a;
int &r = a;
```

Если грубо:

- указатель хранит адрес, и с ним можно работать как с отдельным значением;
- ссылка ведет себя так, будто это сам объект, только под другим именем.

| Характеристика | Указатель | Ссылка |
| -------------- | --------- | ------ |
| Может быть не инициализирован | да | нет |
| Может быть `nullptr` | да | нет, нормальная ссылка должна ссылаться на объект |
| Можно переназначить | да | нет |
| Доступ к объекту | `*p` | `r` |
| Может требовать проверки | часто да | обычно нет |

Поэтому после объявления:

```cpp
int a = 5;
int &b = a;
```

имя `b` почти везде означает сам объект `a`.

```cpp
b = 10; // меняет a
```

А что будет, если написать `&b`?

```cpp
int *p1 = &a;
int *p2 = &b;
```

`&b` даст адрес объекта `a`, потому что `b` — это ссылка на `a`. То есть в обычной ситуации `&a` и `&b` дают один и тот же адрес.

Это еще раз показывает отличие от указателя. Если бы `b` был указателем, то `&b` означало бы "адрес самого указателя". Но `b` — ссылка, поэтому `&b` означает "адрес объекта, на который ссылка ссылается".

Важно: ссылка сама по себе не спасает от UB. Если вернуть ссылку на объект, который уже умер, получится висячая ссылка.

```cpp
int &bad() {
    int x = 5;
    return x; // UB: возвращаем ссылку на локальную переменную
}
```

После выхода из функции локальная переменная `x` уничтожена. Ссылка осталась, но объекта уже нет. Это ровно тот случай, где можно начинать грустить.

## `const`-ссылки

Обычная неконстантная ссылка должна ссылаться на уже существующий изменяемый объект:

```cpp
int a = 5;
int &r = a; // можно
```

К временному значению ее привязать нельзя:

```cpp
int &a = 5; // нельзя
```

А `const`-ссылка может:

```cpp
const int &a = 5; // можно
```

C++ продлевает время жизни временного объекта до времени жизни такой ссылки. Поэтому это нормально:

```cpp
const int &x = 2 + 3;
```

На практике `const T&` часто используют для передачи больших объектов без копирования:

```cpp
struct Big {
    int data[1000];
};

void print(const Big &x);
```

Так объект не копируется, но функция обещает его не менять.

Для маленьких типов вроде `int`, `double`, указателей обычно проще и быстрее передавать по значению:

```cpp
void f(int x);        // нормально
void g(const int &x); // обычно лишнее усложнение
```

## Инициализация в C++

В C++ объектов создается сильно больше, чем кажется. Поэтому синтаксис инициализации важен.

```cpp
int a = 2;
int b(2);
int c{2};
```

Здесь появились три разные формы:

- `= 2` — привычная инициализация через `=`;
- `(2)` — инициализация через круглые скобки;
- `{2}` — инициализация через фигурные скобки.

Для `int` эти формы почти одинаковые. Но для пользовательских типов разница может быть важной, потому что вызываются конструкторы. До конструкторов мы еще дойдем, пока важно увидеть сам синтаксис.

Фигурные скобки часто удобнее:

```cpp
int x{5};
int arr[3]{1, 2, 3};
```

В `arr[3]` квадратные скобки не являются новым способом инициализации. Это старый синтаксис массива: `arr` — массив из трех `int`. А вот `{1, 2, 3}` — список значений, которыми массив инициализируется.

То есть:

```cpp
int arr[3]{1, 2, 3};
```

означает примерно то же самое по смыслу, что:

```cpp
int arr[3] = {1, 2, 3};
```

Со структурами фигурные скобки тоже работают. Если в структуре одно поле:

```cpp
struct One {
    int x;
};

One a{10}; // x = 10
```

Если полей несколько, значения идут по порядку объявления полей:

```cpp
struct Point {
    int x;
    int y;
};

Point p{10, 20}; // x = 10, y = 20
```

Порядок важен именно тот, который написан в структуре:

```cpp
struct Pair {
    int first;
    int second;
};

Pair p{1, 2}; // first = 1, second = 2
```

Они также помогают избежать странного правила C++:

```cpp
struct S {
    S() {}
};

S a;   // объект
S b(); // не объект, а объявление функции b, возвращающей S
S c{}; // объект
```

Это называется most vexing parse. Если запись можно понять как объявление функции, C++ часто именно так ее и поймет.
