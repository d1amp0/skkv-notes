--------------------------------------------------------------------------------

CMake — это система настройки сборки проекта. Он сам обычно не компилирует C/C++ напрямую, а генерирует файлы для другой системы сборки: Make, Ninja, Visual Studio project files и т.д.

--------------------------------------------------------------------------------
## Зачем нужен CMake

Маленькую программу можно собрать одной командой:

```bash
g++ main.cpp -o app
```

Но в реальном проекте быстро появляются:

- несколько `.cpp`;
- заголовочные файлы;
- библиотеки;
- разные флаги компиляции;
- разные операционные системы;
- Debug/Release-сборки.

Писать длинную команду компилятора руками становится неудобно. CMake описывает проект в файле `CMakeLists.txt`, а потом генерирует сборку под конкретную среду.

--------------------------------------------------------------------------------
## Минимальный `CMakeLists.txt`

Пример проекта:

```text
project/
├── CMakeLists.txt
└── main.cpp
```

Минимальный `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.16)

project(MyApp)

add_executable(my_app main.cpp)
```

Смысл:

- `cmake_minimum_required` — минимальная версия CMake;
- `project(MyApp)` — имя проекта;
- `add_executable(my_app main.cpp)` — собрать исполняемый файл `my_app` из `main.cpp`.

--------------------------------------------------------------------------------
## Как запустить сборку

Обычно сборку делают не прямо в папке с исходниками, а в отдельной папке `build`.

```bash
cmake -S . -B build
cmake --build build
```

Первая команда:

```bash
cmake -S . -B build
```

говорит:

- `-S .` — исходники находятся в текущей папке;
- `-B build` — файлы сборки положить в папку `build`.

Вторая команда:

```bash
cmake --build build
```

запускает реальную сборку через сгенерированную систему сборки.

--------------------------------------------------------------------------------
## Несколько `.cpp`

Если файлов несколько:

```text
project/
├── CMakeLists.txt
├── main.cpp
├── math.cpp
└── math.h
```

можно написать:

```cmake
add_executable(my_app
    main.cpp
    math.cpp
)
```

Заголовочный файл `math.h` обычно не указывают как исходник для компиляции. Его подключают через `#include`, а компилируются именно `.cpp`.

--------------------------------------------------------------------------------
## Стандарт C++

Чтобы указать стандарт языка:

```cmake
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
```

Это означает: проекту нужен C++20, и CMake должен требовать именно его.

Часто это пишут после `project(...)`.

--------------------------------------------------------------------------------
## Include-директории

Если заголовки лежат в отдельной папке:

```text
project/
├── CMakeLists.txt
├── src/
│   └── main.cpp
└── include/
    └── math.h
```

то компилятору нужно сказать, где искать заголовки:

```cmake
add_executable(my_app
    src/main.cpp
)

target_include_directories(my_app PRIVATE include)
```

`target_include_directories` относится к конкретной цели `my_app`.

`PRIVATE` здесь означает: эта include-директория нужна для сборки самой цели, но не является частью интерфейса для других целей.

--------------------------------------------------------------------------------
## Библиотеки в CMake

Можно собрать не только исполняемый файл, но и библиотеку:

```cmake
add_library(math_lib
    math.cpp
)
```

Потом подключить библиотеку к программе:

```cmake
add_executable(my_app
    main.cpp
)

target_link_libraries(my_app PRIVATE math_lib)
```

Смысл `target_link_libraries`: цель `my_app` должна линковаться с `math_lib`.

Это напрямую связано с этапом линковки: компилятор отдельно собирает объектные файлы, а линкер соединяет их в итоговую программу.

--------------------------------------------------------------------------------
## `PRIVATE`, `PUBLIC`, `INTERFACE`

В CMake часто встречаются слова `PRIVATE`, `PUBLIC`, `INTERFACE`.

Для первого понимания:

- `PRIVATE` — нужно только самой цели;
- `PUBLIC` — нужно самой цели и тем, кто будет использовать эту цель;
- `INTERFACE` — не нужно самой цели, но нужно тем, кто ее использует.

Например:

```cmake
target_include_directories(math_lib PUBLIC include)
```

Это значит: `math_lib` использует заголовки из `include`, и программа, которая линкуется с `math_lib`, тоже должна знать про эту include-директорию.

--------------------------------------------------------------------------------
## Debug и Release

Сборки часто бывают разных типов:

- `Debug` — удобнее для отладки, обычно без сильных оптимизаций;
- `Release` — оптимизированная сборка.

Для одноконфигурационных генераторов часто пишут:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
```

Или:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Детали зависят от генератора, но сама идея такая: CMake хранит настройки сборки, а потом по ним запускается компиляция.
