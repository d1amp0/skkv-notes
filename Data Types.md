--------------------------------------------------------------------------------

В языке C тип определяет, как интерпретируется память, какие операции допустимы над значением и какие соглашения ввода-вывода нужно соблюдать.

--------------------------------------------------------------------------------
## Базовые типы

### `int`

- Базовый знаковый целочисленный тип.
- Эквивалентные записи: `int` = `signed` = `signed int`.
- Минимальный гарантированный диапазон: `-32767 ... 32767`.
- Это означает, что тип `int` должен иметь не менее 16 бит значения.

```c
int a = 239;
```

### `void`

- Обозначает отсутствие значения.
- Используется как тип возвращаемого значения функции без результата.
- В списке параметров `void` означает, что функция не принимает аргументов.

```c
void log_message(void) {
    printf("ok\n");
}
```

--------------------------------------------------------------------------------
## Дополнительные целочисленные типы

### `unsigned int`

- Беззнаковая версия `int`.
- Эквивалентные записи: `unsigned` = `unsigned int`.
- Размер совпадает с `int`: `sizeof(unsigned int) == sizeof(int)`.
- Минимальный гарантированный диапазон: `0 ... 65535`.
- Переполнение для беззнаковых типов определено стандартом как арифметика по модулю.

### `short`

- Эквивалентные записи: `short` = `short int` = `signed short` = `signed short int`.
- Беззнаковая форма: `unsigned short` = `unsigned short int`.
- По стандарту `sizeof(short) <= sizeof(int)`.
- Минимальный гарантированный диапазон для знаковой формы: `-32767 ... 32767`.
- Минимальный гарантированный диапазон для беззнаковой формы: `0 ... 65535`.
- Это тоже как минимум 16-битный целый тип.

### `long`

- Эквивалентные записи: `long` = `long int` = `signed long` = `signed long int`.
- Беззнаковая форма: `unsigned long` = `unsigned long int`.
- По стандарту `sizeof(long) >= sizeof(int)`.
- Минимальный гарантированный диапазон для знаковой формы: `-2147483647 ... 2147483647`.
- Минимальный гарантированный диапазон для беззнаковой формы: `0 ... 4294967295`.
- Это как минимум 32-битный целый тип.
- Точный размер зависит от реализации, поэтому `long` не используют как тип "строго известной ширины".

### `long long`

- Эквивалентные записи: `long long` = `long long int` = `signed long long` = `signed long long int`.
- Беззнаковая форма: `unsigned long long` = `unsigned long long int`.
- По стандарту `sizeof(long long) >= sizeof(long)`.
- Минимальный гарантированный диапазон для знаковой формы: `-9223372036854775807 ... 9223372036854775807`.
- Минимальный гарантированный диапазон для беззнаковой формы: `0 ... 18446744073709551615`.
- Это как минимум 64-битный целый тип.

### `char`

- `char` имеет размер ровно `1` байт: `sizeof(char) == 1`.
- При этом байт в стандарте C не обязан быть равен 8 битам, но обязан содержать как минимум 8 бит: `CHAR_BIT >= 8`.
- `char`, `signed char` и `unsigned char` — это три разных типа.
- У обычного `char` знаковость не фиксирована стандартом: он может вести себя либо как `signed char`, либо как `unsigned char`.
- Для `signed char` минимальный гарантированный диапазон: `-127 ... 127`.
- Для `unsigned char` минимальный гарантированный диапазон: `0 ... 255`.
- Если нужен именно числовой смысл, лучше явно использовать `signed char` или `unsigned char`.

### Типы фиксированного размера

- Как можно было понять выше, типы `int`, `short`, `long`, `char` не гарантируют определённого значения, а лишь диапазон. Для этого могут помочь типы фиксированного размера.
- `<stdint.h>` содержит `int8_t`, `uint8_t`, `int16_t`, `uint16_t`, `int32_t`, `uint32_t`, `int64_t`, `uint64_t`.
- Они существуют только тогда, когда реализация действительно может предоставить целый тип ровно такой ширины.

### `_Bool и bool`

- `_Bool` появился в C99.
- `bool` в C — это макрос из `<stdbool.h>`, который разворачивается в `_Bool`.
- Хранит логическое значение: по смыслу `0` или `1`.
- Минимально `_Bool` должен уметь хранить значения `0` и `1`; точный `sizeof(_Bool)` стандартом не фиксирован.
- Имена `bool`, `true`, `false` традиционно дает `<stdbool.h>`.

### `size_t`

- Беззнаковый целочисленный тип.
- Предназначен для хранения размера объектов в байтах.
- Размер равен размеру [[Pointers and arrays#Что такое указатель|указателя]].

### `ptrdiff_t`

- Знаковый целочисленный тип.
- Предназначен для для хранения разности двух указателей.
- Имеет тот же размер, что и `size_t`.

### `_BitInt(N) из C23`

- Семейство целочисленных типов произвольной битности.
- Есть знаковая и беззнаковая формы: `_BitInt(N)` и `unsigned _BitInt(N)`.
- Поддержка зависит от компилятора.

## Типы с плавающей точкой

Типы с плавающей точкой нужны для хранения нецелых чисел:

```c
float x = 0.5f;
double y = 3.14;
```

Но важно сразу не обмануться: `float` и `double` — это не "вещественные числа из математики". В математике между `0` и `1` бесконечно много значений, а в памяти компьютера любое значение хранится конечным числом бит.

Поэтому типы с плавающей точкой хранят только конечное множество чисел. Многие привычные десятичные дроби представляются приблизительно.

Классический пример:

```c
double x = 0.1;
```

Число `0.1` в двоичной системе является бесконечной периодической дробью. В памяти бесконечную дробь хранить нельзя, поэтому сохраняется ближайшее представимое значение. Подробнее это разобрано в [[ArcEvm#Числа с фиксированной точкой (Fixed Point)|разделе про дробные числа]] и [[ArcEvm#Числа с плавающей точкой (Floating Point)|floating point]].

--------------------------------------------------------------------------------
### Общая идея floating-point

Число с плавающей точкой хранится примерно в виде:

```text
sign * mantissa * base^exponent
```

Для двоичной арифметики основание обычно равно `2`:

```text
(-1)^sign * mantissa * 2^exponent
```

То есть в памяти хранятся три смысловые части:

- знак;
- мантисса;
- экспонента.

Мантисса отвечает за значащие цифры, то есть за точность. Экспонента отвечает за масштаб числа, то есть за диапазон.

Из-за этого floating-point умеет хранить и очень маленькие, и очень большие числа, но расстояние между соседними представимыми числами меняется. Чем дальше число от нуля по модулю, тем крупнее шаг между соседними значениями.

Это главное отличие от целых типов. У `int` соседние значения всегда отличаются на `1`. У `float` рядом с `1.0` шаг маленький, а рядом с очень большим числом шаг уже намного больше.

--------------------------------------------------------------------------------
### IEEE-754 и стандарт C

На практике `float` и `double` почти всегда связаны с IEEE-754:

| Формат | Обычно в C | Размер | Экспонента | Мантисса |
| ------ | ---------- | ------ | ---------- | -------- |
| single precision | `float` | 32 бита | 8 бит | 23 бита |
| double precision | `double` | 64 бита | 11 бит | 52 бита |
| extended precision | `long double` на некоторых платформах | 80 бит | 15 бит | зависит от формата |

Но стандарт C формулирует требования осторожнее. Он не говорит: "`float` обязан быть ровно IEEE-754 single precision". Вместо этого стандарт задает минимальные гарантии по диапазону и точности, а конкретная реализация описывает детали через `<float.h>`.

Например:

```c
#include <float.h>
```

В этом заголовке есть макросы:

- `FLT_DIG` — сколько десятичных значащих цифр надежно хранит `float`;
- `DBL_DIG` — аналогично для `double`;
- `LDBL_DIG` — аналогично для `long double`;
- `FLT_MIN`, `DBL_MIN`, `LDBL_MIN` — минимальные положительные нормализованные значения;
- `FLT_MAX`, `DBL_MAX`, `LDBL_MAX` — максимальные конечные значения.

--------------------------------------------------------------------------------
### `float`

`float` — самый маленький стандартный тип с плавающей точкой.

- Размер `float` в байтах стандартом не фиксирован.
- Минимальная гарантия по точности: `FLT_DIG >= 6`.
- Обычно соответствует IEEE-754 single precision: 32 бита.
- Обычно имеет примерно 6-7 десятичных значащих цифр точности.
- Используется, когда важны экономия памяти, пропускная способность или совместимость с форматами данных/графикой/ускорителями.

```c
float x = 3.14f;
```

Суффикс `f` важен: без него литерал `3.14` имеет тип `double`.

```c
float a = 3.14;  // 3.14 сначала double, потом преобразуется к float
float b = 3.14f; // сразу float
```

Для одного числа это не трагедия, но в большом численном коде лучше понимать, где `float`, а где `double`.

--------------------------------------------------------------------------------
### `double`

`double` — основной рабочий тип с плавающей точкой в C.

- Размер `double` в байтах стандартом не фиксирован.
- По точности и диапазону `double` не уже, чем `float`.
- Минимальная гарантия по точности: `DBL_DIG >= 10`.
- Обычно соответствует IEEE-754 double precision: 64 бита.
- Обычно имеет примерно 15-16 десятичных значащих цифр точности.

```c
double x = 3.14;
```

Если написать дробный литерал без суффикса, он имеет тип `double`:

```c
3.14   // double
3.14f  // float
3.14L  // long double
```

Именно поэтому `double` часто выбирают по умолчанию для обычных вычислений: точность заметно выше, чем у `float`, а на современных процессорах работа с `double` обычно хорошо поддерживается.

--------------------------------------------------------------------------------
### `long double`

`long double` — тип с плавающей точкой, который должен быть не хуже `double`.

- Размер `long double` в байтах стандартом не фиксирован.
- По точности и диапазону `long double` не уже, чем `double`.
- Минимальная гарантия по точности: `LDBL_DIG >= DBL_DIG`.
- На разных платформах может быть тем же самым, что `double`, 80-битным extended precision или 128-битным форматом.

```c
long double x = 3.14L;
```

Суффикс `L` делает литерал `long double`.

С `long double` надо быть осторожным в переносимом коде. На одной платформе он может давать дополнительную точность, а на другой почти не отличаться от `double`.

--------------------------------------------------------------------------------
### `_Float16`

`_Float16` — тип для 16-битного floating-point, появившийся в современных стандартах/расширениях C.

- Обычно соответствует half precision.
- Требует поддержки компилятора и платформы.
- Имеет намного меньшую точность, чем `float`.
- Полезен там, где важна плотность хранения и скорость обработки большого количества чисел: графика, нейросети, ускорители.

У half precision обычно:

- 1 бит знака;
- 5 бит экспоненты;
- 10 бит мантиссы.

То есть диапазон и точность сильно ограничены. Это не "маленький double", а отдельный компромиссный формат.

--------------------------------------------------------------------------------
### Нормализованные и денормализованные числа

Обычное floating-point число хранится в нормализованном виде. У него мантисса имеет скрытую ведущую единицу:

```text
1.xxxxx * 2^e
```

Это экономит один бит: ведущая `1` подразумевается, но обычно не хранится явно.

Но около нуля появляется проблема. Если использовать только нормализованные числа, между нулем и минимальным нормализованным числом была бы резкая дырка.

Для этого существуют денормализованные, или subnormal, числа:

- экспонента имеет специальное минимальное значение;
- скрытая ведущая единица превращается в `0`;
- можно представить очень маленькие числа ближе к нулю.

Идея подробно разобрана в [[ArcEvm#Денормализованные числа|ArcEvm]].

--------------------------------------------------------------------------------
### Бесконечности и `NaN`

В отличие от целых типов, floating-point умеет хранить специальные значения.

Бесконечность:

- `+inf` — положительная бесконечность;
- `-inf` — отрицательная бесконечность.

Например, при IEEE-754 деление положительного ненулевого числа на `0.0` может дать `+inf`.

```c
double x = 1.0 / 0.0; // обычно +inf в IEEE-754
```

`NaN` означает Not a Number.

Он появляется в ситуациях, где результат не является нормальным числом:

```c
double x = 0.0 / 0.0; // обычно NaN
```

Важнейшее свойство:

```c
NaN != NaN
```

Даже если переменная содержит `NaN`, сравнение самой с собой через `==` даст ложь:

```c
double x = 0.0 / 0.0;

if (x == x) {
    // для NaN сюда не попадем
}
```

Для нормальной проверки используют функции из `<math.h>`, например `isnan`, `isinf`, `isfinite`.

```c
#include <math.h>

if (isnan(x)) {
    // x является NaN
}
```

--------------------------------------------------------------------------------
### Округление и потеря точности

Floating-point арифметика почти всегда связана с округлением.

Например:

```c
double x = 0.1 + 0.2;
```

Математически результат равен `0.3`, но в памяти может получиться ближайшее представимое значение, которое чуть-чуть отличается от `0.3`.

Поэтому сравнивать дробные числа через `==` часто опасно:

```c
double x = 0.1 + 0.2;

if (x == 0.3) {
    // лучше так не писать
}
```

Обычно сравнивают с допустимой погрешностью:

```c
#include <math.h>

double diff = fabs(x - 0.3);

if (diff < 1e-9) {
    // считаем числа достаточно близкими
}
```

Это не "баг C", а прямое следствие конечного числа бит и двоичного представления дробей.

--------------------------------------------------------------------------------
### Арифметика и продвижение типов

В выражениях `float` часто продвигается до `double` в старых соглашениях вызова функций и при работе с variadic-функциями вроде `printf`.

Например:

```c
float x = 1.5f;
printf("%f\n", x);
```

Для `printf` спецификатор `%f` ожидает `double`, и `float` передается как `double` из-за default argument promotions.

В обычных арифметических выражениях тип результата зависит от обычных арифметических преобразований:

```c
float f = 1.0f;
double d = 2.0;

double x = f + d; // f преобразуется к double
```

Если один операнд `double`, а другой `float`, вычисление идет в `double`.

--------------------------------------------------------------------------------
### Форматы из архитектуры вычислений

Во второй половине курса всплывают и другие форматы:

- half precision;
- bfloat16;
- сверхкороткие форматы вроде `e5m2` и `e4m3`.

Они важны для архитектуры вычислений, ускорителей и ИИ, но требуют особенно осторожного отношения к точности, переполнению и поведению специальных значений.

Идея у них похожая: есть знак, экспонента и мантисса. Но количество бит распределено иначе.

Например, `bfloat16` сохраняет широкую экспоненту, похожую на `float`, но сильно урезает мантиссу. Поэтому диапазон у него большой, а точность низкая.

--------------------------------------------------------------------------------
### Что важно запомнить

- `float`, `double`, `long double` отличаются не просто размером, а балансом точности и диапазона.
- Дробные числа часто хранятся приблизительно.
- `double` — обычный тип по умолчанию для дробных литералов и большинства вычислений.
- `float` экономит память, но быстрее теряет точность.
- `long double` зависит от платформы сильнее, чем хочется.
- У floating-point есть специальные значения: `+inf`, `-inf`, `NaN`.
- `NaN` не равен даже самому себе.
- Сравнение дробных чисел через `==` часто заменяют сравнением с погрешностью.

### Комплексные числа

- В C есть поддержка комплексных чисел, например `_Complex float`.
- Это не "магия языка", а полноценный числовой тип со своей арифметикой и библиотечной поддержкой.

## Соотношения размеров, которые гарантирует стандарт

Для стандартных целочисленных типов полезно помнить общую цепочку:

`sizeof(char) <= sizeof(short) <= sizeof(int) <= sizeof(long) <= sizeof(long long)`

Так как `sizeof(char) == 1`, все остальные размеры выражаются в байтах относительно него.

При этом стандарт не требует, чтобы байт был ровно 8 бит, хотя на практике это почти всегда так.

## Спецификаторы форматирования

Спецификатор форматирования должен соответствовать типу значения. Несовпадение формата и фактического типа — типичная причина ошибок.

### `%i`

- Используется для `int`.
- В `scanf` читает целое число и пропускает ведущие пробелы.

### `%u`

- Используется для `unsigned int`.

### `%lld`

- Используется для `long long int` в десятичной записи.

### `%lli`

- Также относится к `long long int`.
- Часто используется при вводе через `scanf`.

### `%llx`

- Используется для шестнадцатеричного представления `long long int`.

```c
long long int x;
unsigned int y;

scanf("%lld", &x);
scanf("%lli", &x);
scanf("%llx", &x);
scanf("%u", &y);
```
