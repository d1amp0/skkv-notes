--------------------------------------------------------------------------------

В C динамическая память обычно означает `malloc`, `calloc`, `realloc`, `free`. В C++ появились `new` и `delete`. Главное отличие: `new` не просто выделяет память, а еще запускает конструктор. `delete` не просто освобождает память, а еще вызывает деструктор.

--------------------------------------------------------------------------------
## Обычное создание объекта и динамическое создание

До этого мы создавали объекты примерно так:

```cpp
int x = 5;
```

или так:

```cpp
struct S {
    int x;
};

S s{10};
```

В таких примерах мы не пишем отдельное выделение памяти. Но память все равно где-то берется. Просто управляет этим не программист напрямую:

- локальный объект обычно живет в стековом кадре функции;
- глобальный объект живет в области глобальных/статических данных;
- объект создается при входе в свою область видимости и уничтожается при выходе из нее.

Например:

```cpp
void f() {
    S s{10};
} // здесь s уничтожается автоматически
```

А `new` нужен, когда объект должен жить не по правилам текущей области видимости, а пока мы сами явно его не удалим.

```cpp
S *p = new S{10};
delete p;
```

Здесь `p` — обычная локальная переменная-указатель. А сам объект `S`, на который указывает `p`, создан в динамической памяти.

Где именно выделяет память `new`? В области динамической памяти. В C++ эту область часто называют free store. На практике для первого понимания можно считать, что это та же большая идея, что и куча у `malloc`: память живет, пока ее явно не освободят.

То есть:

- `malloc` выделяет память в куче;
- обычный `new` выделяет память в динамической памяти/free store;
- в обычных реализациях это очень близкие области, но освобождать их нужно разными средствами.

Объект, созданный через `new`, не уничтожится автоматически при выходе из блока, его нужно удалить через `delete`.

Сравним два случая.

Обычный локальный объект:

```cpp
S *p = nullptr;

{
    S s{10};
    p = &s;
} // здесь s уничтожился

// p теперь хранит старый адрес, но объекта S там уже нет
```

Такой указатель после блока использовать нельзя: он указывает на объект, время жизни которого закончилось.

А теперь динамическое создание:

```cpp
S *p = nullptr;

{
    p = new S{10};
} // локальная переменная-блок закончилась, но объект S жив

delete p; // уничтожили объект вручную
```

Во втором примере объект, созданный через `new`, не привязан к концу блока. Из блока исчезает только локальная переменная, если она там была. Сам динамический объект живет до `delete`.

## `new` и `delete` для простого типа

Начнем не со структуры, а с обычного `int`:

```cpp
int *p = new int;
delete p;
```

Что делает `new int`:

1. Выделяет память под один `int`.
2. Создает там объект типа `int`.
3. Возвращает указатель на этот объект.

`delete p` уничтожает объект и освобождает выделенную память.

Можно сразу задать начальное значение:

```cpp
int *p = new int(5);
delete p;
```

или через фигурные скобки:

```cpp
int *p = new int{5};
delete p;
```

После `delete` указатель `p` сам по себе не исчезает, но адрес в нем становится старым адресом уже уничтоженного объекта. Использовать `*p` после `delete` нельзя.

## `new` и `delete` для структур

Для структуры смысл тот же, но добавляется вызов конструктора и деструктора:

```cpp
struct S {
    int x;

    S(int value) : x(value) {}
    ~S() {}
};

S *p = new S(10);
delete p;
```

Что делает `new S(10)`:

1. Выделяет память под объект `S`.
2. Вызывает конструктор `S(10)`.
3. Возвращает указатель на созданный объект.

Что делает `delete p`:

1. Вызывает деструктор объекта.
2. Освобождает память.

Это принципиальное отличие от `malloc/free`.

```cpp
S *p = (S *)std::malloc(sizeof(S)); // только сырая память
std::free(p);                       // только освобождение памяти
```

`malloc` не вызывает конструктор, `free` не вызывает деструктор. Для C++-объектов это почти всегда не то, что нужно.

## Скалярный и массивный `new`

Один объект:

```cpp
S *p = new S(1);
delete p;
```

Массив объектов:

```cpp
S *p = new S[10];
delete[] p;
```

Это разные операции. Если выделили через `new[]`, освобождать нужно через `delete[]`.

```cpp
S *p = new S[10];
delete p; // UB
```

Почему это важно? Для массива нужно вызвать деструктор у каждого элемента, а для одного объекта — только у одного. Реализация должна знать, какой сценарий перед ней.

Что происходит с самими структурами при `new S[10]`?

Если у структуры есть конструктор по умолчанию, он будет вызван для каждого элемента массива:

```cpp
struct S {
    int x;

    S() : x(0) {}
};

S *p = new S[10]; // 10 раз вызывается S()
delete[] p;       // 10 раз вызывается деструктор S
```

То есть это не просто "кусок памяти под 10 структур". Это массив из 10 живых объектов `S`.

Если конструктора по умолчанию нет, такой массив создать не получится:

```cpp
struct S {
    int x;

    S(int value) : x(value) {}
};

S *p = new S[10]; // нельзя: непонятно, как создать каждый S без аргумента
```

Можно задать значения через фигурные скобки:

```cpp
S *p = new S[3]{S{1}, S{2}, S{3}};
delete[] p;
```

А если структура совсем простая и конструктора нет:

```cpp
struct Point {
    int x;
    int y;
};

Point *a = new Point[10];   // поля int внутри элементов не получают полезные значения
Point *b = new Point[10]{}; // элементы инициализируются нулями

delete[] a;
delete[] b;
```

Разница важная: `new Point[10]` создает объекты, но для простых `int`-полей без явной инициализации значения будут неопределенными. А `new Point[10]{}` выполняет value-initialization, поэтому поля зануляются.

## `new` и неудачное выделение памяти

`malloc` при неудаче возвращает `NULL`.

Обычный `new` при неудаче бросает исключение `std::bad_alloc`:

```cpp
S *p = new S[1000000000000];
```

Про исключения будет отдельный раздел позже. Пока достаточно понимать так: если памяти нет, обычный `new` не возвращает `nullptr`, а сообщает об ошибке через механизм исключений. Если эту ошибку никто не обработал, программа аварийно завершится.

Есть вариант `std::nothrow`:

```cpp
#include <new>

S *p = new (std::nothrow) S[10];
if (p == nullptr) {
    // памяти не хватило
}
```

Такой `new` не бросает исключение, а возвращает `nullptr`.

## У `new` нет аналога `realloc`

В C можно сделать:

```c
p = realloc(p, new_size);
```

У `new[]` прямого аналога нет. Если нужен массив другого размера, обычно создают новый массив, переносят данные и удаляют старый:

```cpp
int *old_data = new int[10];

int *new_data = new int[20];

for (int i = 0; i < 10; ++i) {
    new_data[i] = old_data[i];
}

delete[] old_data;
old_data = new_data;
```

Порядок здесь важен:

1. Сначала выделили новый массив.
2. Потом скопировали старые элементы.
3. Потом удалили старый массив.
4. Потом сохранили новый адрес в переменную `old_data`.

В реальном C++ для таких задач обычно используют `std::vector`, но пока важно понимать сам механизм.

## Placement new

Обычный `new` делает две вещи сразу:

1. Выделяет память.
2. Создает объект в этой памяти, то есть вызывает конструктор.

Placement new нужен, когда память уже есть, и нужно сделать только вторую часть: создать объект по заранее выбранному адресу.

Зачем такое может понадобиться?

- Есть заранее выделенный большой буфер, и мы хотим вручную размещать в нем объекты.
- Пишется свой контейнер или аллокатор.
- Нужно отделить выделение памяти от конструирования объекта.
- В низкоуровневом коде память может приходить не от обычного `new`, а из специальной области.

Простой пример:

```cpp
#include <new>
#include <cstdlib>

struct S {
    S() {}
    ~S() {}
};

void *raw = std::malloc(sizeof(S));
S *p = new (raw) S; // конструируем S в уже выделенной памяти

p->~S();       // вручную вызываем деструктор
std::free(raw);
```

Здесь `std::malloc(sizeof(S))` выделил сырую память. В этой памяти еще нет живого объекта `S`; это просто набор байтов подходящего размера.

`new (raw) S` не выделяет память. Он только вызывает конструктор по адресу `raw`, то есть превращает эту сырую память в живой объект `S`.

Именно поэтому потом нельзя писать просто `delete p`: память выделялась не через обычный `new`. Нужно вручную вызвать деструктор и освободить память тем способом, которым она была выделена.

Если написать такое:

```cpp
S *p;
p = new (p) S; // UB: p не указывает на валидную память
```

то это бессмыслица. Placement new требует настоящий адрес подходящего участка памяти.

## Смешивать `malloc/free` и `new/delete` нельзя

Правило простое:

| Выделили | Освобождаем |
| -------- | ----------- |
| `malloc/calloc/realloc` | `free` |
| `new` | `delete` |
| `new[]` | `delete[]` |
| placement new | явный деструктор + освобождение исходной памяти |

Неверная пара — UB.

```cpp
int *p = new int;
std::free(p); // UB

int *q = (int *)std::malloc(sizeof(int));
delete q; // UB
```

Иногда это не падает сразу. Это не значит, что код правильный.

## `new/delete` и RAII

Писать `new/delete` руками можно, но это источник ошибок:

- забыли `delete` — утечка;
- вызвали `delete` дважды — double free;
- перепутали `delete` и `delete[]` — UB;
- бросилось исключение между `new` и `delete` — можно потерять память.

Поэтому C++ обычно старается прятать владение ресурсом внутрь объекта, у которого есть деструктор. Это было описано в [[C++ lifetime#RAII|RAII]].

Сырой `new` в прикладном коде — подозрительное место. Для учебных целей он нужен, чтобы понимать механику. Для нормального кода чаще используют стандартные контейнеры и умные указатели.
