--------------------------------------------------------------------------------

Этот раздел про владение ресурсами в современном C++: правило пяти, перемещение, `std::move`, `noexcept` и `std::unique_ptr`.

--------------------------------------------------------------------------------
## Зачем вообще нужно перемещение

В C++ объект часто владеет ресурсом:

- динамической памятью;
- открытым файлом;
- сокетом;
- mutex-ом;
- любым объектом, который нельзя просто побайтово скопировать.

Копирование такого объекта может быть дорогим или вообще неправильным.

Например, если объект владеет буфером, обычная копия должна выделить новый буфер и скопировать данные. Но иногда старый объект нам больше не нужен. Тогда вместо копирования можно "забрать" у него ресурс.

Это и есть идея перемещения: не создать независимую копию, а перенести владение из одного объекта в другой.

## `std::move`

`std::move` сам по себе ничего не двигает.

Он делает одну конкретную вещь: превращает выражение в rvalue-выражение, точнее в `xvalue`.

Если сказать проще: `std::move(a)` не перемещает объект `a`, а разрешает использовать `a` как источник для перемещения.

```cpp
String a("hello");
String b(std::move(a));
```

Что здесь происходит по шагам:

1. `a` — обычный именованный объект. Выражение `a` является `lvalue`.
2. `std::move(a)` превращает выражение `a` в `xvalue`.
3. Из-за этого компилятор выбирает конструктор перемещения `String(String&&)`, если такой конструктор есть.
4. Уже сам конструктор перемещения решает, как перенести внутренности объекта.

То есть важно разделять две операции:

- `std::move(a)` — только меняет категорию выражения;
- `String b(...)` — вызывает подходящий конструктор, и вот он уже реально выполняет копирование или перемещение.

Если у типа есть нормальный перемещающий конструктор, то в примере выше `b` забирает ресурс у `a`. Например, строка может передать `b` указатель на свой внутренний буфер, а `a` оставить в пустом, но корректном состоянии.

После перемещения объект `a` не уничтожен. Он остается живым и валидным: его можно уничтожить, ему можно присвоить новое значение, его можно использовать только в тех операциях, которые не требуют старого содержимого.

```cpp
String a("hello");
String b(std::move(a));

a = String("new text"); // нормально: a получил новое значение
```

Но после перемещения нельзя логически рассчитывать, что в `a` все еще лежит `"hello"`.

```cpp
String a("hello");
String b(std::move(a));

// Плохо как идея: состояние a после перемещения не стоит использовать
// как будто оно осталось прежним.
```

Если у типа нет перемещающего конструктора, `std::move` не создаст его магически. Тогда может быть выбран копирующий конструктор, если он подходит.

```cpp
struct S {
    S(const S &other) {}
};

S a;
S b(std::move(a)); // вызовется копирование, потому что move-конструктора нет
```

Вот откуда иногда появляется ощущение "может переместить, а может не переместить". Точнее так: `std::move` всегда делает выражение подходящим для перемещения, но реальное перемещение зависит от того, есть ли у типа подходящая перемещающая операция.

## Категории значений

Чтобы понять перемещение до конца, нужно аккуратно разобрать категории значений.

В C часто хватает грубой идеи:

- есть выражения, у которых можно взять адрес и которые обозначают существующий объект;
- есть временные результаты вычислений.

В C++ это формализовано подробнее, потому что от категории выражения зависит:

- можно ли присваивать в это выражение;
- можно ли взять у него адрес;
- какую ссылку к нему можно привязать;
- будет ли выбран копирующий или перемещающий конструктор.

Важно: категория значения относится не к типу переменной, а к выражению.

```cpp
int x = 5;
```

У `x` тип `int`. Но выражение `x` имеет категорию `lvalue`.

```cpp
x + 1;
```

У выражения `x + 1` тоже тип `int`, но категория уже другая: это временный результат вычисления.

### `lvalue`

`lvalue` — выражение, которое обозначает существующий объект, у которого есть устойчивое место в памяти.

```cpp
int x = 5;
x = 10;
```

`x` здесь — `lvalue`. У него есть имя, место в памяти, его можно использовать слева от `=`.

```cpp
int *p = &x; // можно
```

Примеры `lvalue`:

```cpp
int x = 5;
int *p = &x;

x;     // lvalue
*p;    // lvalue: разыменованный указатель обозначает объект
p[0];  // lvalue
```

Название историческое: `lvalue` можно понимать как left value, то есть значение, которое часто может стоять слева от присваивания. Но это не идеальное определение. Например, `const int x = 5;` тоже дает `lvalue`, хотя писать `x = 10` нельзя из-за `const`.

Обычная ссылка `T&` привязывается именно к таким выражениям:

```cpp
int &r = x; // можно
int &bad = 5; // нельзя
```

### `prvalue`

`prvalue` означает pure rvalue. Это выражение, которое вычисляет значение, но не обозначает уже существующий именованный объект.

```cpp
5;          // prvalue
x + 1;      // prvalue
make_int(); // prvalue, если функция возвращает int по значению
```

Например, `x + 1` вычисляется и дает результат, но это не переменная `x`, у которой можно спокойно взять адрес и менять ее дальше.

В старом объяснении часто говорят: prvalue — это временное значение. Для первого понимания это нормально.

```cpp
int x = 5;
int y = x + 1; // результат x + 1 используется для инициализации y
```

Само выражение `x + 1` не является отдельной переменной, которую можно потом изменить.

```cpp
(x + 1) = 10; // нельзя
```

К временному значению можно привязать `const T&`:

```cpp
const int &r = 5; // можно
```

И можно привязать rvalue-ссылку:

```cpp
int &&r = 5; // можно
```

### `xvalue`

`xvalue` означает expiring value. Это выражение, которое обозначает существующий объект, но этот объект рассматривается как ресурс, из которого разрешено "забрать внутренности".

Самый важный практический источник `xvalue` — `std::move`:

```cpp
std::move(x);
```

После такого выражения компилятор может выбрать перемещающий конструктор или перемещающее присваивание.

Важно: сам `x` никуда не исчезает.

```cpp
std::move(x);
```

не перемещает объект автоматически. Это только меняет категорию выражения: выражение `x` было `lvalue`, а выражение `std::move(x)` стало `xvalue`.

Именно после этого перегрузки могут выбрать вариант с `T&&`.

```cpp
void f(const String &s); // копировать/читать
void f(String &&s);      // можно забрать ресурс

String s("hello");

f(s);            // s — lvalue, выберется f(const String&)
f(std::move(s)); // std::move(s) — xvalue, выберется f(String&&)
```

### Именованная rvalue-ссылка сама является lvalue

Это место часто ломает голову.

```cpp
int &&r = 5;
```

`r` имеет тип `int&&`, то есть это rvalue-ссылка. Но выражение `r` является `lvalue`, потому что у него есть имя.

```cpp
int &&r = 5;

int &a = r; // можно: выражение r — lvalue
```

Если нужно снова получить rvalue из `r`, надо написать `std::move(r)`:

```cpp
int &&b = std::move(r);
```

Именно поэтому в перемещающих конструкторах часто пишут `std::move` для полей:

```cpp
struct S {
    String name;

    S(S &&other) : name(std::move(other.name)) {}
};
```

`other` имеет тип `S&&`, но выражение `other` — lvalue, потому что у него есть имя. То же самое с `other.name`.

### `glvalue`

`glvalue` означает generalized lvalue. Это общее название для выражений, которые обозначают какой-то объект или функцию.

В эту группу входят:

- `lvalue`;
- `xvalue`.

Почему здесь уже понятно, что такое `xvalue`: это выражение, которое тоже обозначает объект, но объект считается "истекающим", то есть подходящим для перемещения.

Слово `glvalue` нужно в основном для полной схемы категорий. В практическом коде чаще рассуждают про `lvalue`, `rvalue`, `prvalue` и `xvalue`.

### `rvalue`

`rvalue` — общее название для выражений, которые можно считать "временными" или "готовыми к перемещению".

В эту группу входят:

- `prvalue`;
- `xvalue`.

То есть `rvalue` — не одна конкретная категория, а объединение двух категорий.

Примеры:

```cpp
5;            // prvalue, значит rvalue
x + 1;        // prvalue, значит rvalue
std::move(x); // xvalue, значит rvalue
```

Обычная неконстантная ссылка `T&` к rvalue не привязывается:

```cpp
int &a = 5; // нельзя
```

А rvalue-ссылка `T&&` привязывается:

```cpp
int &&a = 5; // можно
```

### Общая схема

Полная схема выглядит так:

```text
expression
├── glvalue
│   ├── lvalue
│   └── xvalue
└── rvalue
    ├── prvalue
    └── xvalue
```

На практике для первого понимания достаточно:

- `T&` — ссылка на обычный существующий объект;
- `const T&` — ссылка и на обычный объект, и на временное значение;
- `T&&` — rvalue-ссылка, через нее реализуют перемещение;
- `std::move(x)` — превращает `x` в выражение, из которого можно перемещать.

### Таблица для запоминания

| Категория | Что означает | Примеры | Можно ли обычной ссылке `T&` привязаться | К чему обычно привязывается |
| --------- | ------------ | ------- | ----------------------------------------- | --------------------------- |
| `lvalue` | существующий объект с устойчивым местом в памяти | `x`, `*p`, `arr[i]` | да | `T&`, `const T&` |
| `prvalue` | временный результат вычисления | `5`, `x + 1`, `make_object()` | нет | `const T&`, `T&&` |
| `xvalue` | существующий объект, из которого разрешено перемещать | `std::move(x)` | нет | `const T&`, `T&&` |
| `glvalue` | общее название для `lvalue` и `xvalue` | `x`, `std::move(x)` | зависит от подкатегории | зависит от подкатегории |
| `rvalue` | общее название для `prvalue` и `xvalue` | `5`, `x + 1`, `std::move(x)` | нет для обычной `T&` | `const T&`, `T&&` |

Самая полезная практическая цепочка такая:

```cpp
String s("hello");

s;            // lvalue: обычный именованный объект
String("hi"); // prvalue: временный объект
std::move(s); // xvalue: тот же s, но разрешено перемещать
```

Поэтому `std::move` не "перемещает", а делает выражение подходящим для перемещения.

## Rvalue-ссылки

Rvalue-ссылка записывается как `T&&`.

```cpp
int &&r = 5;
```

Ее главный смысл: привязаться к временному значению или к объекту, который явно разрешили использовать как временный через `std::move`.

```cpp
int x = 5;

int &a = x;             // обычная ссылка на lvalue
const int &b = 5;       // const-ссылка может продлить жизнь временного значения
int &&c = 5;            // rvalue-ссылка на временное значение
int &&d = std::move(x); // rvalue-ссылка на x, который разрешили перемещать
```

Обычная ссылка `T&` говорит: "мне нужен существующий объект, который не является временным результатом".

```cpp
int &r = x; // можно
int &q = 5; // нельзя
```

Rvalue-ссылка `T&&` говорит: "я готов принять временный объект или объект, из которого разрешено забирать ресурс".

```cpp
int &&r = 5; // можно
```

Для `int` это выглядит не очень полезно. Настоящий смысл появляется у объектов, которые владеют ресурсами:

```cpp
Buffer make_buffer();

Buffer a = make_buffer(); // результат функции можно переместить
Buffer b = std::move(a);  // из a явно разрешили забрать ресурс
```

Именно поэтому перемещающий конструктор принимает `T&&`:

```cpp
Buffer(Buffer &&other) noexcept;
```

Смысл параметра `other`: это объект, который еще жив, но из него можно забрать ресурс, потому что вызывающий код передал временный объект или написал `std::move`.

Очень важная ловушка: если rvalue-ссылка получила имя, то само это имя является `lvalue`.

```cpp
void f(Buffer &&other) {
    Buffer a(other);            // other — lvalue, тут может выбраться копирование
    Buffer b(std::move(other)); // теперь снова разрешили перемещение
}
```

Именно поэтому `std::move` часто встречается внутри перемещающих конструкторов и операторов.

## Конструктор перемещения

Конструктор перемещения обычно принимает `T&&`:

```cpp
struct Buffer {
    char *p;

    Buffer(Buffer &&other) noexcept {
        p = other.p;
        other.p = nullptr;
    }
};
```

Что происходит:

1. Новый объект забирает указатель `other.p`.
2. Старый объект обнуляется, чтобы его деструктор не освободил тот же ресурс второй раз.

Это не глубокая копия. Буфер остался тот же, просто сменился владелец.

Почему здесь написан `noexcept`?

Перемещение часто используется стандартными контейнерами при перераспределении памяти. Например, `std::vector` может переносить элементы в новый буфер. Если перемещение обещает не бросать исключения, контейнеру проще сохранить корректное состояние при ошибках и он охотнее выбирает move вместо copy.

Поэтому перемещающий конструктор ресурсо-владеющего класса обычно пишут с `noexcept`:

```cpp
Buffer(Buffer &&other) noexcept;
```

## Оператор перемещающего присваивания

Перемещающее присваивание работает с уже существующим объектом:

```cpp
struct Buffer {
    char *p = nullptr;

    Buffer &operator=(Buffer &&other) noexcept {
        if (this != &other) {
            std::free(p);
            p = other.p;
            other.p = nullptr;
        }
        return *this;
    }
};
```

Сначала текущий объект освобождает свой старый ресурс, потом забирает ресурс у `other`.

Проверка `this != &other` защищает от странного самоприсваивания через перемещение.

`noexcept` здесь нужен по той же причине, что и в перемещающем конструкторе: перемещение ресурсов обычно должно быть дешевой операцией без исключений, а стандартные контейнеры учитывают это свойство.

## Правило пяти

Раньше было правило трех:

- деструктор;
- конструктор копирования;
- копирующее присваивание.

В современном C++ к ним добавились еще две операции:

- конструктор перемещения;
- перемещающее присваивание.

Итого получается правило пяти: если класс вручную управляет ресурсом, нужно подумать обо всех пяти специальных функциях.

```cpp
struct S {
    S();
    ~S();

    S(const S &);
    S &operator=(const S &);

    S(S &&) noexcept;
    S &operator=(S &&) noexcept;
};
```

Каждая из этих функций отвечает за отдельную жизненную ситуацию объекта:

| Функция | Как выглядит | Когда вызывается | Зачем нужна |
| ------- | ------------ | ---------------- | ----------- |
| Деструктор | `~S()` | объект уничтожается | освободить ресурс: память, файл, сокет и т.д. |
| Конструктор копирования | `S(const S &other)` | создается новый объект как копия другого | сделать независимую копию ресурса |
| Копирующее присваивание | `S &operator=(const S &other)` | уже существующему объекту присваивают другой объект | заменить текущий ресурс копией чужого ресурса |
| Конструктор перемещения | `S(S &&other) noexcept` | создается новый объект из временного или из `std::move(other)` | забрать ресурс у другого объекта без глубокого копирования |
| Перемещающее присваивание | `S &operator=(S &&other) noexcept` | уже существующему объекту присваивают временный объект или `std::move(other)` | освободить старый ресурс и забрать новый |

Коротко по ситуациям:

```cpp
S a;          // обычный конструктор
S b = a;      // конструктор копирования
b = a;        // копирующее присваивание

S c = make(); // конструктор перемещения, если make() возвращает временный S
c = make();   // перемещающее присваивание

S d = std::move(a); // конструктор перемещения
d = std::move(b);   // перемещающее присваивание
```

Почему правило пяти вообще появляется?

Если класс владеет ресурсом через сырой указатель, компилятор не понимает смысл владения. Для него указатель — просто адрес. Поэтому автоматически сгенерированная копия обычно скопирует сам адрес, а не объект, на который он указывает.

```cpp
struct Buffer {
    char *data;
};
```

Если два `Buffer` будут хранить один и тот же `data`, оба деструктора могут попытаться освободить одну и ту же память. Поэтому классам с ручным владением нужно явно описывать, что значит копирование, присваивание, перемещение и уничтожение.

Если не хочется разрешать копирование, его можно удалить через `= delete`, а перемещение оставить.

## `std::unique_ptr`

`std::unique_ptr<T>` — умный указатель, который единолично владеет объектом.

```cpp
#include <memory>

std::unique_ptr<int> p(new int{5});
```

Когда `p` уничтожится, он сам вызовет `delete` для объекта.

Главная идея: `unique_ptr` ведет себя как указатель на объект, но с правилом единоличного владения. В нормальной модели владения ровно один `unique_ptr` отвечает за удаление этого объекта.

То есть формулировка "больше указателей на этот объект быть не может" почти передает идею, но ее надо уточнить: обычные не владеющие указатели или ссылки технически могут смотреть на тот же объект, но владельцем остается только один `unique_ptr`.

```cpp
std::unique_ptr<int> owner(new int{5});

int *raw = owner.get(); // можно посмотреть адрес, но raw не владеет объектом
```

`raw` нельзя удалять через `delete`. Он просто наблюдает за объектом, а удалит объект `owner`.

Именно из-за единоличного владения `unique_ptr` нельзя копировать:

```cpp
std::unique_ptr<int> a(new int{5});
std::unique_ptr<int> b = a; // нельзя
```

Но можно перемещать:

```cpp
std::unique_ptr<int> b = std::move(a); // теперь владелец b
```

После этого `a` больше не владеет объектом.

В реальном C++ обычно пишут не `new` напрямую, а `std::make_unique`:

```cpp
auto p = std::make_unique<int>(5);
```
