--------------------------------------------------------------------------------

Стандартные контейнеры C++ — это готовые типы из стандартной библиотеки, которые хранят наборы объектов и сами управляют памятью внутри себя.

--------------------------------------------------------------------------------
## Что такое контейнер

Контейнер — это объект, внутри которого хранится несколько других объектов.

Примеры задач:

- хранить список чисел;
- хранить набор строк;
- хранить очередь задач;
- хранить пары "ключ-значение".

В C для динамического массива часто приходилось вручную писать `malloc`, `realloc`, `free`, следить за размером и вместимостью:

```c
int *data = malloc(sizeof(int) * 10);
```

В C++ для таких задач обычно используют контейнеры. Они прячут ручное управление памятью внутрь себя.

```cpp
std::vector<int> data;
```

Пока `std::vector<int>` можно читать так: "вектор, который хранит `int`". Почему там угловые скобки, подробно разбирается в [[C++ templates#Шаблоны классов|шаблонах классов]].

Контейнер — это не магический массив. Это обычный объект C++, у которого есть поля, методы, конструктор, деструктор и правила копирования/перемещения.

--------------------------------------------------------------------------------
## `std::vector`

`std::vector<T>` — динамический массив из стандартной библиотеки.

Главная идея: элементы лежат подряд в памяти, как в обычном массиве, но размер можно менять во время работы программы.

```cpp
#include <vector>

std::vector<int> v;
```

Изначально `v` пустой.

Добавить элемент в конец можно через `push_back`:

```cpp
v.push_back(10);
v.push_back(20);
v.push_back(30);
```

Теперь в векторе три элемента:

```cpp
v[0]; // 10
v[1]; // 20
v[2]; // 30
```

Количество элементов:

```cpp
int n = v.size();
```

Технически `size()` возвращает беззнаковый тип `std::size_t`, но для первого понимания важно, что это текущий размер вектора.

--------------------------------------------------------------------------------
## Размер и вместимость

У `vector` есть два похожих, но разных понятия:

- `size()` — сколько элементов сейчас реально хранится;
- `capacity()` — под сколько элементов уже выделена память внутри.

Пример:

```cpp
std::vector<int> v;

v.push_back(1);
v.push_back(2);
v.push_back(3);
```

Вектор может выделить память с запасом. Например, элементов сейчас 3, а память уже выделена под 4 или 8 элементов. Точное число зависит от реализации.

Зачем запас? Чтобы не выделять новую память при каждом `push_back`.

Когда места хватает, `push_back` просто создает новый элемент в уже выделенной области.

Когда места не хватает, `vector` обычно:

1. выделяет новый блок памяти побольше;
2. переносит или копирует туда старые элементы;
3. добавляет новый элемент;
4. уничтожает старые элементы в старом блоке;
5. освобождает старую память.

Вот почему для `vector` важны конструкторы копирования, перемещения и `noexcept` у перемещения.

## Доступ к элементам

Через `[]` можно получить элемент по индексу:

```cpp
std::vector<int> v;

v.push_back(10);
v.push_back(20);

int x = v[1]; // 20
```

Но `[]` не проверяет выход за границы:

```cpp
int x = v[100]; // ошибка времени выполнения/UB, если такого элемента нет
```

Есть метод `at`, который проверяет границы:

```cpp
int x = v.at(1); // 20
int y = v.at(100); // ошибка через исключение
```

Про исключения уже было в [[C++ modern features#Исключения|разделе про исключения]].

## Инициализация `vector`

Вектор можно сразу создать с элементами:

```cpp
std::vector<int> v{1, 2, 3};
```

Можно создать вектор заданного размера:

```cpp
std::vector<int> v(5);
```

Здесь будет 5 элементов `int`, и они будут инициализированы нулями.

Можно создать вектор заданного размера и значения:

```cpp
std::vector<int> v(5, 7);
```

Это значит: 5 элементов, каждый равен 7.

Важно не перепутать:

```cpp
std::vector<int> a{5};    // один элемент: 5
std::vector<int> b(5);    // пять элементов: 0 0 0 0 0
std::vector<int> c(5, 7); // пять элементов: 7 7 7 7 7
```

## `std::initializer_list`

`std::initializer_list<T>` — специальный легкий объект, который позволяет функции или конструктору принять список значений в фигурных скобках.

```cpp
#include <initializer_list>

void print_all(std::initializer_list<int> values) {
    for (int x : values) {
        // используем x
    }
}

print_all({1, 2, 3});
```

Именно поэтому многие стандартные контейнеры можно создавать так:

```cpp
std::vector<int> v{1, 2, 3};
```

У `vector` есть конструктор, который принимает `std::initializer_list<int>`.

Важно: `initializer_list` сам не владеет отдельным динамическим массивом как `vector`. Его удобно понимать как временный вид на набор константных элементов, созданных компилятором для выражения `{...}`.

Элементы внутри `initializer_list` нельзя менять через него:

```cpp
void f(std::initializer_list<int> values) {
    for (int x : values) {
        // x — копия элемента
    }
}
```

Если написать ссылку, она будет ссылкой на `const int`:

```cpp
void f(std::initializer_list<int> values) {
    for (const int &x : values) {
        // x читать можно, менять нельзя
    }
}
```

Еще из-за `initializer_list` появляется важная разница между круглыми и фигурными скобками:

```cpp
std::vector<int> a(5, 7); // пять элементов со значением 7
std::vector<int> b{5, 7}; // два элемента: 5 и 7
```

Фигурные скобки здесь выбирают конструктор от `initializer_list`.

## `vector` и обычный массив

Обычный массив:

```cpp
int a[3]{1, 2, 3};
```

Размер такого массива фиксирован. Нельзя просто добавить четвертый элемент.

`vector`:

```cpp
std::vector<int> v{1, 2, 3};
v.push_back(4);
```

Вектор сам решит, нужно ли выделять новую память.

При этом элементы `vector` лежат подряд в памяти. Это значит, что `vector` хорошо подходит как замена динамического массива в большинстве обычных задач.

--------------------------------------------------------------------------------
## Важная опасность ссылки и указатели на элементы

Если взять адрес элемента вектора:

```cpp
std::vector<int> v{1, 2, 3};

int *p = &v[0];
```

а потом вектору понадобится перераспределить память:

```cpp
v.push_back(4);
v.push_back(5);
```

старый указатель `p` может стать висячим. Причина: элементы могли переехать в новый блок памяти.

То же самое касается ссылок и итераторов на элементы вектора.

## `std::span`

`std::span<T>` — невладеющий вид на непрерывный участок памяти.

Он не хранит элементы сам. Он хранит примерно две вещи:

- указатель на первый элемент;
- количество элементов.

```cpp
#include <span>
#include <vector>

void print(std::span<int> data) {
    for (int x : data) {
        // используем x
    }
}
```

Такую функцию можно вызвать и с массивом, и с `vector`:

```cpp
int a[3]{1, 2, 3};
std::vector<int> v{4, 5, 6};

print(a);
print(v);
```

Смысл `span`: функция не владеет данными, а только временно смотрит на них.

Это удобнее, чем передавать отдельно указатель и размер:

```cpp
void print(int *data, int size);
```

`span` связывает адрес и размер в один объект:

```cpp
void print(std::span<int> data);
```

Но раз `span` не владеет данными, он не продлевает их жизнь.

```cpp
std::span<int> bad;

{
    std::vector<int> v{1, 2, 3};
    bad = v;
} // v уничтожился

// bad теперь смотрит в уничтоженную память
```

То есть `span` безопасен только пока жив объект, на данные которого он смотрит.

## `std::unordered_map`

`std::unordered_map<K, V>` — контейнер для пар "ключ-значение".

```cpp
#include <unordered_map>
#include <string>

std::unordered_map<std::string, int> age;
```

Здесь:

- ключ — `std::string`;
- значение — `int`.

Можно записывать значения по ключу:

```cpp
age["Ann"] = 20;
age["Bob"] = 25;
```

И читать:

```cpp
int x = age["Ann"]; // 20
```

Но у `operator[]` есть важное поведение: если ключа нет, он создаст новый элемент со значением по умолчанию.

```cpp
int y = age["Kate"]; // ключа не было, он появится со значением 0
```

Если нужно только проверить наличие ключа, лучше использовать `find`:

```cpp
auto it = age.find("Kate");

if (it != age.end()) {
    int value = it->second;
} else {
    // ключа нет
}
```

`it->first` — ключ, `it->second` — значение.

Почему контейнер называется `unordered_map`?

Потому что он не хранит элементы в отсортированном порядке. Внутри обычно используется хеш-таблица:

1. ключ превращается в хеш;
2. по хешу выбирается внутренняя корзина;
3. в этой корзине ищется нужный ключ.

Из-за этого поиск, вставка и удаление в среднем работают быстро, примерно за `O(1)`. Но порядок обхода элементов не стоит считать осмысленным.

```cpp
for (const auto &p : age) {
    // p.first  — ключ
    // p.second — значение
}
```

Порядок вывода может быть не таким, как порядок вставки.
